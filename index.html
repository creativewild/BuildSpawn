How a build flows

From a submit to a store branch

Someone submits a change. Buildspawn builds it on the right machines, runs the tests and sends the game to the store. Click a stage to see its page.

Game / Windows Build · Submitted changes
01 · Submit

Every changelist, and the build that took it

Buildspawn watches Perforce and Git. A submit can start a build at once, through a trigger on the Perforce server, or on a polling timer.

  • Changelists with the first build that contained each one.
  • Perforce streams and shelves, and several roots in one build configuration.
  • Builds on a schedule or after another build, too.
Build every Perforce submit
Agents
02 · Build on agents

The right machine for every build

Agents sit in pools, such as Windows or Linux. A build only goes to an agent that has what it needs, and the queue says why a build waits.

  • Live CPU, memory, disk, network and GPU for each agent.
  • Pools with their own icon and colour.
  • Steps can run side by side on several agents.
The Agents page
Engine / Unit Tests #2 · Test Result
03 · Test

Know at once what broke

Test reports from NUnit, VSTest, JUnit XML and more show on the build. Failed tests come first, and new failures are marked as regressions.

  • Failure conditions on exit codes, log text, time and test counts.
  • Retry a flaky step on its own.
  • Resume a failed build from the step that failed.
Find out why a build failed
Game / Steam Nightly · Console
04 · Publish

Straight to Steam and the Epic Games Store

Store steps upload the build and put it on a branch. Store passwords stay in credentials and are hidden in the log.

  • 6 Steam steps: install SteamCMD, upload, check, DRM wrap, set live and workshop.
  • 8 Epic Games Store steps, from upload to label and clean up.
  • Steam Guard is handled for you.
Upload to a Steam branch

Parallel steps

Build every platform at once

A Parallel block runs its sides at the same time, on one agent or on several. Matrix mode writes the steps once for each platform and configuration.

Build console

A build log you can read

Each step is a block with its result, warnings and time. Scripts add their own blocks with ::group::. Filter to errors only, or search the log.

HT1 Unreal Windows Build · Edit build step

One step for every Unreal job

Make a packaged game with BuildCookRun, run a BuildGraph script on one agent or many, run automation tests or a commandlet. The step finds the engine on the agent.

  • Launcher installs and source builds.
  • Errors and warnings picked out of the engine log.
  • Post a badge to Unreal Game Sync.
Unreal Engine stepBuild Unreal from Perforce
HT1 Unity Windows Build · Edit build step

Unity in batch mode

Build a player, use a build profile, run your own build method or run the project's tests. The step finds the Unity Editor on the agent.

  • Players for Windows, Linux, Mac and Android.
  • Edit-mode and play-mode tests.
  • Unity licence kept as a credential.
Unity stepBuild Unity from Git
Promote to Drop · Edit build step

Perforce first

Define a Perforce root once and use it in many builds. The Perforce operations step syncs, submits, shelves, copies streams and labels, with no password in any script.

  • Streams, shelves and view mappings as a table.
  • Shelf checks before submit.
  • Depot browser, changelists and labels.

Game / Steam Release · Build steps

Steam, step by step

Steam Release installs SteamCMD, uploads the depots, checks the build, wraps it with DRM, sets a branch live and updates a workshop item.

  • A Steam build account credential, with Steam Guard.
  • A preview of the build script the step writes.
  • Setting a branch live needs its own permission.
Steam overviewUnity from Perforce to Steam
Game / Epic Publish · Build steps

The Epic Games Store, end to end

Epic Publish installs the BuildPatch Tool, uploads the build, optimises the patch and labels it. More steps copy, download, inspect or delete binaries.

  • An Epic Games Store credential.
  • Agents report where the BuildPatch Tool is.
  • Secrets hidden in the log.
Epic Games StorePublish to the Epic Games Store
Agents · Pools · Windows

A pool for every platform

Group your build machines in pools, such as Windows and Linux. Give each pool to the projects that need it, so their builds land on the right machines.

  • An icon and a colour for each pool.
  • Pools show in the Agents side panel and the agent list.
  • Move agents between pools by hand or on a schedule.
