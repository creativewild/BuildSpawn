The server terminal program

buildspawn is a program for the command line that sets up, starts, watches and changes your Buildspawn server on Linux, macOS and Windows.

It is in every server download: bin/buildspawn on Linux and macOS, bin\buildspawn.exe on Windows. The Linux packages and the Windows setup also put it on the PATH, so you type just buildspawn. A short introduction is in Get started: the terminal program. The table of every command, flag and key is in Terminal program commands. This page explains how the program behaves.

When to use it

Use it on a server you reach over SSH, on a Mac or Linux box without a desktop, or when you want to script checks. It manages the same service, settings file and folders as the other tools, so it never disagrees with them. On Windows it works next to the Windows app.

Two modes: the interface and single commands

Type buildspawn with no command to open the full-screen interface. It opens the launch flow on a first run, and the live monitor after that. A first run means: no settings file, no service installed and no server running.

The interface opens only in a real terminal. In a scheduled task, a pipe or with --no-tui, the program prints the status as text instead. A command such as buildspawn status does one job and exits.

The launch flow

The launch flow sets Buildspawn up in five steps. Nothing is changed until you press Start on the last step. At any time: Enter goes on, Esc goes back, Tab moves between fields, Space ticks a box, ? is help and q quits.

The start screen: presets

If you have saved presets they are listed first, each with its home, port and how it runs, plus three more choices: Set up from the beginning, Use an existing home folder… (pick a folder that already holds Buildspawn data) and Open the monitor only. Press e, d or n to edit, delete or rename the selected preset. A preset keeps the home, port, who can connect, memory and the run options, so you can set up a second server the same way.

Preset names may use letters, digits, space, dot, dash and underscore, up to 40 characters. The file is presets.json in your user configuration folder. See Where presets are saved.

buildspawn launch --preset build-box --yes
buildspawn preset list
buildspawn preset save build-box
buildspawn preset delete build-box

--preset skips the start screen. --yes accepts every default.

The live monitor

The monitor reads the server's REST API and refreshes every 2 seconds (change it with --interval). The top line shows the version, the state and address, how long it has run, and LIVE or FROZEN. Press 1 to 7 or Tab to change view. Two layouts exist: 110 columns or wider, and a narrow one from 80 to 109 columns.

ViewWhat it shows
1 OverviewTiles: Server, Builds running (executors in use), Queue, Builds / hour, Success rate (24 hours), Agents, JVM heap, CPU and Disk free · home, each with a bar or trend strip, and a Recent builds list. Tab moves between tiles, Enter opens a build's log.
2 BuildsThe last 24 hours: start time, build configuration, number, result, time and agent. / filters by name, agent or cause. f cycles the result filter (all, running, failed, unstable and more), g groups by build configuration, Enter shows the selected build's log, o opens it in the browser and x stops it.
3 QueueEvery waiting item, how long it has waited, and why it waits. Filter by reason: blocked, waiting, offline, quiet period, lock. c cancels the item, p moves it to the front.
4 AgentsEach agent with its state, executors in use, labels, system and free disk. Enter shows executors, o opens the agent page, d takes it offline and n starts adding a new agent.
5 LogsA log with a Source (Tab): the systemd journal (Linux service) or buildspawn.log, gc.log (the Java memory log) or a build log. l sets the level (ALL, INFO, WARN, SEVERE), / filters, f turns follow on and off, PgUp and PgDn scroll, c clears and s saves.
6 ServiceThe service: Unit, State, Start at boot, Runs as, Listens on, Home, Settings file, Java and Recent unit events. See below.

Read only, and the token

Without an API token the monitor is read only. Stopping a build (x), cancelling or moving a queue item (c, p) and taking an agent offline (d) need one, and the status line says so. The Service and Settings views work without a token. Give a token with --token-file PATH or the variable BUILDSPAWN_TOKEN_FILE. The file holds one line: user:token. The program never prints the token. Create one in your user's Security page, as described in API tokens.

echo "dana.k:11a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6" > ~/.buildspawn-token
chmod 600 ~/.buildspawn-token
buildspawn --token-file ~/.buildspawn-token --view queue

Stop, cancel and restart always ask first and name what they end.

The Service view

It controls the service for this copy of Buildspawn: s start, t stop, r restart, i install or update the unit, u remove it (all data stays) and a start at boot on or off. A note warns that Stop and Restart end the running builds. Windows asks for permission (UAC) when needed.

The Settings view

The view edits the settings file and keeps its comments. The fields are Port, Listen address, Home folder, Logs folder, Java memory (max), Java options and Extra arguments. ↑ ↓ select a field, Enter edits it and Esc cancels the edit. Each row shows saved or what is pending, and a Checks box warns about a port in use or memory that is too big. A memory bar shows the heap against the computer's memory.

  • a applies and restarts. A box Restart with these settings? asks first and names the builds that would end.
  • w saves and applies later (at the next restart).
  • u undoes your changes.

The box also shows the matching text command, for example buildspawn set port=9090 memory=6g --apply. See Settings files for what each key does.

Quitting

q opens Close the monitor. It says how the server runs. k keeps the server serving, s stops the server (with the number of running builds), and Esc stays. If the monitor itself started the server, only Stop or Stay is offered. Ctrl + C quits and keeps the server running.

Look and feel

  • t cycles the colour theme: color, light and mono. G cycles the symbols: unicode, ascii and solid. Space freezes the screen.
  • Without a terminal, or with NO_COLOR or --no-color, you get the mono theme.
  • The old Windows console gets ASCII symbols and 16 colours, with a note in the status line. Windows Terminal gets unicode and full colour. BUILDSPAWN_GLYPHS=unicode|ascii|solid changes it.

The text twins

Every view has a command that prints the same facts as text, or as JSON with --json:

CommandTwin of
buildspawn statusOverview. Exit code 0 when the server runs, 3 when it is stopped.
buildspawn builds [--running | --failed] [--limit N]Builds
buildspawn queueQueue, with the reason each item waits
buildspawn agentsAgents
buildspawn logs [-f] [--level warn] [--filter TEXT] [--source gc]Logs. With no option it follows the log.
buildspawn service status | install | remove | enable | disableService
buildspawn set key=value ... [--apply] [--yes]Settings
 
buildspawn status --json
buildspawn builds --failed --limit 5
buildspawn --once --view agents --no-color

--once draws one frame of a view as plain text and exits, which suits a log file or a chat message.

Watching another server

Add --url (or BUILDSPAWN_URL) to watch a server on another computer. The Service and Settings views, and start, stop and set, always act on the server of the computer you run the program on.

buildspawn --url https://build.example.com/ --token-file ~/.buildspawn-token --view builds

Start, stop and the service

  • buildspawn run runs the server in this terminal until Ctrl + C. The services use this command.
  • buildspawn start, stop and restart use the service when one is installed for this copy, otherwise they start or stop a background server.
  • buildspawn install-service [--user NAME] [--no-start] [--dry-run] installs and starts the service. --user is for Linux: the system user to run as (default buildspawn). uninstall-service [--remove-user] removes it and keeps the home, logs and settings. --dry-run only says what would be done.
  • buildspawn check checks the settings file and Java, and prints the full Java command.
  • buildspawn admin-password [--copy] prints, or copies, the initial admin password while it exists.

Buildspawn runs either as the service or in the terminal or background on one home, never both. The program keeps a lock file, buildspawn.pid, in the home folder and refuses to start a second server on it.

Trusted certificates: buildspawn certs

This command manages the same trust folder as Settings › Security › Trusted certificates, for company root certificates that Java must trust. It works on this computer's home folder, and does not need the server to run. Changes take effect when the server starts again.

CommandWhat it does
buildspawn certs listShows the trust folder, the state of the Windows store setting, the added certificates, and whether a restart is needed.
buildspawn certs add <file>Adds the certificates in a .pem .crt .cer .der .p7b or .p7c file. It shows each one first and asks before adding. Use - instead of a file to read the text from standard input (this needs --yes).
buildspawn certs remove <fingerprint or name>Removes one added certificate. The fingerprint may be just its start, with or without colons. If several match, the program lists them.
buildspawn certs windows-store on|offAlso trust the certificates the Windows certificate store trusts. Windows only.

Options: --yes does not ask, --include-expired (with add) also adds expired certificates, and --home DIR names the home folder when it cannot be found from the settings file. A private key in the input is refused and not kept.

buildspawn certs add company-root.crt
buildspawn certs list
buildspawn certs remove 3F:9A:C1

Problems and fixes

ProblemWhat to do
The monitor says the server asks for sign-in (HTTP 403): pass --token-file.The server needs a user for its API. Give a token file as described above.
The status shows Not reachable.The server is not running, or listens on another port. Run buildspawn status and buildspawn check.
Start says another server holds the home folder.Stop the service or the background server first. One home, one server.
The screen is garbled in a very old console.Use --glyphs ascii and --theme mono, or --once.
buildspawn prints text and does not open the interface.The program saw no terminal. Run it in a real terminal window and leave out --no-tui.
