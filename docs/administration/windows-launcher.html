The Windows app

Buildspawn.exe is the window you use to start, stop and set up the Buildspawn server on a Windows computer.

Every Windows download of the server includes the app. It has five tabs: Run here, Settings, Windows service, Certificates and About. Open it from the Start menu (Buildspawn) or run Buildspawn.exe from the program folder. A short walk-through is in Get started: the Windows app. This page lists every control.

The app is for the server. The small program for a build agent is described in The agent tray app.

Buildspawn runs either inside the app or as the Windows service, on one data folder, never both at once. The app checks this and tells you which one is running.

When to use it

Use the app to try Buildspawn out, to change its settings with a form instead of a text file, to install the Windows service, and to add your company's root certificates. On a server that nobody signs in to, install the service once and then you rarely open the app.

Run here

This tab starts Buildspawn inside the app, for this signed-in user. It stops when you stop it or close the app (see the tray icon below).

The tray icon

When you close the window while Buildspawn runs here, a question appears: Buildspawn is still running here. Stop it, or keep it running with an icon in the notification area? The buttons are Keep running in the tray, Stop and close and Cancel.

The tray icon (the notification area at the bottom right) has a menu:

Menu itemWhat it does
Open BuildspawnShows the app window again.
Open in browserOpens the web interface.
StopStops the server.
ExitCloses the app.

Hover over the icon to see the state. If the server stops by itself, a balloon tells you why.

The buttons

The app checks the form as you type. It reports a port outside 1 to 65535, a memory size that is not like 4g, less than 512 MB, or as much as the whole computer, and folders that are not full paths or cannot be created.

Windows service

The service starts with Windows, runs without anybody signed in, and restarts Buildspawn if it stops. This tab shows its state and controls it.

ItemWhat it shows or does
ServiceNot installed, Running (starts with Windows, restarts on failure), Stopped and so on.
ProgramThe program the service runs. A note appears when it is another copy of Buildspawn than this one. Remove it, then install again, to use this copy.
AccountNT AUTHORITY\LocalService by default.
DataThe data folder the service uses.
Install, RemoveInstall or remove the service. Remove asks first and keeps your settings and data.
Start, Stop, RestartControl the service. Start is disabled while Buildspawn runs here on the same data folder.
Open in browserOpens the service's web address while it runs.

Buttons with a shield icon ask Windows for administrator rights. If you cancel the prompt, the app says Cancelled: Windows did not get administrator rights. A blue note tells you when the settings changed after the service started, and that a restart is needed.

The LocalService account

The service runs as LocalService. This account can change only the data and logs folders. Installing the service also gives it read access to C:\ProgramData\Buildspawn and Modify access to folders named in the Java options. Builds that need more, such as tools or files elsewhere or network shares, need another account. Set it in the Windows Services program, on the Log On tab of Buildspawn, and give that account Modify on the data and logs folders.

The service is set to restart Buildspawn after 10, 30 and 60 seconds if it fails. Read more in Windows services for agents for the agent side.

If Buildspawn stops soon after it starts

The reason is written to the Windows Application event log (source Buildspawn) and to logs\buildspawn.log. Every run adds a line there when it starts (naming whether it is the app or the service, the user and the settings file) and when it stops (with the exit code).

Certificates

It works on the trust folder inside the data folder. The full explanation, and the web page for the same list, are in Trusted certificates.

About

Shows the Buildspawn version and a short licence note: Buildspawn is MIT licensed, and the bundled Java runtime is named with its version. The links Program folder, Settings file and Java notices open those places in Explorer.

Setup: the installer

The installer is buildspawn-<version>-setup.exe. It needs administrator rights and installs the program to C:\Program Files\Buildspawn. It adds Start menu shortcuts, an Apps & features entry, the bin folder on the PATH (so buildspawn works in every new terminal) and, if you choose it, the service.

The wizard

  1. Start setup.exe. The steps on the left are Welcome, Licence, Install folder, Data folder, Port and memory, Options, Install and Finish.
  2. Tick I accept the licence.
  3. Pick the program folder. If Buildspawn is already installed, the wizard says it replaces the program files.
  4. Pick the data folder (default C:\ProgramData\Buildspawn). When settings already exist, the wizard shows them and keeps them. If a service from an unzipped package is found, you can Use the existing service's data and settings. Its service is replaced and its folder stays.
  5. Set the Port (the wizard checks it is free), the Memory and Listen on (This computer only or Network).
  6. On Options tick Install as a Windows service and start it, Start menu shortcuts and a desktop shortcut as you like.
  7. Click Install. On Finish choose Open Buildspawn in the browser and Open the Buildspawn app.

Running a newer setup upgrades the server: it stops the service, replaces the program files, keeps settings and data, and starts the service again. See Backups and upgrades.

Silent install and the switches

buildspawn-<version>-setup.exe /S /PORT=8080 /MEMORY=8g /LISTEN=all /SERVICE=1
SwitchWhat it does
/SInstall or upgrade without questions.
/D=<folder>The program folder. Default C:\Program Files\Buildspawn, or the installed one.
/DATA=<folder>The folder that holds data\ and logs\. Default C:\ProgramData\Buildspawn. Without it, a service from an unzipped package hands over its data and settings.
/PORT=<port>The web port. Default 8080, or the current setting.
/MEMORY=<size>The Java heap, for example 8g.
/LISTEN=all|localhostWhich network interfaces to listen on.
/SERVICE=0|1Install and start the Windows service. Default 1.
/STARTMENU=0|1, /DESKTOP=0|1Shortcuts. Default 1 and 0.
/uninstall [/S] [/DELETEDATA]Removes Buildspawn. Data is kept unless you add /DELETEDATA.
/listLists the package inside the setup.
/extract=<folder>Unpacks the package without installing.
/?Shows all the switches.

A silent run writes its log to %TEMP%\buildspawn-setup.log. To remove Buildspawn use Apps & features or Uninstall Buildspawn in the Start menu. It asks before deleting data, and the default keeps it.

The portable zip

The zip needs no installation. Unpack it anywhere and open Buildspawn.exe. A file named portable in the folder makes the app keep its settings (buildspawn.cfg), data (data\) and logs (logs\) in the same folder, so you can move or copy the whole folder. The zip also has bin\buildspawn.exe, the terminal program, but it does not put bin on the PATH. Add it yourself if you want to type buildspawn.

The service commands

For scripts and remote work, buildspawn-service.exe in the program folder does what the Windows service tab does. Open a command prompt as administrator and go to the program folder:

CommandWhat it does
buildspawn-service installInstalls the service and the Application event log source. Gives LocalService the access it needs.
buildspawn-service uninstallRemoves the service. (remove works too.) Settings and data stay.
buildspawn-service start / stop / restartControl the service. Stop waits until Java has really ended, and after 120 seconds it ends it by force and logs that.
buildspawn-service statusShows the service state.
buildspawn-service checkNeeds no administrator rights. Checks the settings, runs Java with the options, and prints the settings file, data, logs and the full Java command, ending with OK or Not OK.
buildspawn-service runNeeds no administrator rights. Runs Buildspawn in the command prompt until you press Enter. Handy for trying settings.

The old buildspawn.exe console launcher is gone. Buildspawn.exe is the app now. For a console run, use buildspawn-service run. The terminal program is bin\buildspawn.exe, in a folder, so the two never overwrite each other.

Problems and fixes

ProblemWhat to do
Start says the service runs Buildspawn on this data folder.Stop the service on the Windows service tab first, or just open it in the browser.
Service is still stopping... and Start is grey.Wait. Java is still shutting down. The button turns on by itself.
The state is Failed to start.Read the live log and logs\buildspawn.log. Use Check with Java on the Settings tab. A Java option that names a folder that cannot be created is a common cause.
The port is in use.The note beside the port says by whom. Choose another port, or stop the other program.
Save needs a UAC prompt every time.This is normal for an installed copy, because its settings are in C:\ProgramData. The portable copy saves without a prompt.
