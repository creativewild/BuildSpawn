Install on Linux and macOS

Install the Buildspawn server on Linux with a package or a folder, or on a Mac with a folder, and run it as a service.

Every download includes its own Java, so nothing else needs installing. For the short version, see Install the server. This page covers everything in the packages: the files they put on your computer, how to start and stop the server, ports, the home folder, and how to upgrade and remove it.

The packages are for x86-64. You need a Linux with glibc (most distributions; not Alpine). Install fontconfig and a font so that charts can be drawn. The macOS download for your Mac's chip is named -macos-aarch64 (Apple silicon) or -macos-x64 (Intel).

Install a package (Linux)

  1. Download the package and its .sha256 file. Check the download: sha256sum -c buildspawn_<version>_amd64.deb.sha256.
  2. Install it. 
    # Debian, Ubuntu
sudo apt install ./buildspawn_<version>_amd64.deb

# RHEL, Rocky, Fedora
sudo dnf install ./buildspawn-<version>.x86_64.rpm
  3. The package starts the service. Open http://<this machine>:8080/.
  4. Get the initial admin password: sudo buildspawn admin-password. Type it on the setup page and follow the steps. See Your first start.

Where the package puts things

PathWhat it is
/opt/buildspawnThe program: bin/buildspawn, app/buildspawn.war, runtime/ (Java).
/usr/bin/buildspawnA link, so you can type buildspawn.
/etc/default/buildspawn (.deb) or /etc/sysconfig/buildspawn (.rpm)The settings file. See buildspawn.conf.
/var/lib/buildspawnThe home: projects, build history, settings. Back this up.
/var/log/buildspawngc.log and heap dumps. The server log is in the journal.

Builds run as the system user buildspawn, so the tools and files that builds need must be readable by that user.

Everyday commands

sudo systemctl status buildspawn     # or: buildspawn status
sudo buildspawn restart              # or: sudo systemctl restart buildspawn
buildspawn logs                      # the same as: journalctl -u buildspawn -f
buildspawn check                     # checks the settings and Java
sudo buildspawn set port=8090 --apply

Upgrade and remove

Install the new package over the old one with the same command you used to install. The upgrade stops the service, replaces the program, keeps the settings file and the home, and starts the service again. See Backups and upgrades.

GoalCommand
Remove the program. Keeps the settings, the home, the logs and the buildspawn user.sudo apt remove buildspawn or sudo dnf remove buildspawn
Also remove the settings file (Debian, Ubuntu).sudo apt purge buildspawn
Delete the data as well. This cannot be undone.sudo BUILDSPAWN_PURGE_DATA=yes apt purge buildspawn (Debian, Ubuntu)

Install from a folder (tar.gz, Linux and macOS)

The tar.gz holds one folder that is portable. The settings (buildspawn.conf), the home (data/) and the logs (logs/) stay inside it, so you can move or copy the whole folder.

  1. Download the tar.gz for your system and check its .sha256 file.
  2. Unpack it, for example into /opt: 
    tar -xzf buildspawn-<version>-linux-x64.tar.gz -C /opt
cd /opt/buildspawn-<version>-linux-x64
  3. On a Mac, clear the quarantine flag first (see below).
  4. Run bin/buildspawn. On a first run it opens the launch flow, then the live monitor. Press b to open the web page.
  5. To run the server in the terminal without the interface: bin/buildspawn run. Ctrl + C stops it.

macOS: unsigned and not notarized

The Mac download is not signed with an Apple developer ID and is not notarized. When a browser downloads it, macOS marks it as quarantined, and Gatekeeper blocks bin/buildspawn and Java. Unpack it in Terminal and clear the flag from the folder:

shasum -a 256 -c buildspawn-<version>-macos-aarch64.tar.gz.sha256
tar -xzf buildspawn-<version>-macos-aarch64.tar.gz
xattr -dr com.apple.quarantine buildspawn-<version>-macos-aarch64

The bundled Java is signed by its publisher. The bin/buildspawn program is not.

Run it as a service

What it doesCreates the system user buildspawn with no login and gives it data/ and logs/. Logjournalctl -u buildspawn -f or the Logs viewlogs/buildspawn.log

Options for install-service: --user NAME (Linux: run as another user), --no-start and --dry-run. uninstall-service keeps your data, logs and settings. --remove-user (Linux) also deletes the buildspawn user, but not its files. Running install-service again upgrades the unit and restarts the service.

On Linux the buildspawn user must be able to read the folder. Put it in /opt/buildspawn, not in your own home directory. install-service checks this and tells you.

On macOS Buildspawn runs as you, so builds can use your Xcode, keychain and tools. It runs while you are signed in. For a build Mac that must start after a restart with nobody at it, turn on automatic login in System Settings › Users & Groups. The first start from launchd may ask to accept incoming network connections: allow it.

Ports, access and the firewall

  • The web port is BUILDSPAWN_PORT, default 8080. Agents and browsers use it. Change it with buildspawn set port=8090 --apply.
  • BUILDSPAWN_LISTEN is all (every network interface) or localhost (this computer only). Choose all when agents and other people must reach the server.
  • Buildspawn does not change a Linux or macOS firewall. Open the port yourself, for example sudo ufw allow 8080/tcp or sudo firewall-cmd --add-port=8080/tcp --permanent.

Upgrade a folder install

  1. Stop Buildspawn: bin/buildspawn stop.
  2. Unpack the new version into a new folder (on a Mac, clear its quarantine flag).
  3. Copy buildspawn.conf and data/ into the new folder (and logs/ if you want to keep them).
  4. With a service, run the new folder's install-service.sh. It points the service at the new folder.
  5. Start it: bin/buildspawn start.

To copy only the settings next time, set BUILDSPAWN_HOME to a folder outside the program folder, such as /srv/buildspawn. With the Linux service, that folder must belong to the buildspawn user: sudo chown -R buildspawn:buildspawn /srv/buildspawn.

Problems and fixes

ProblemWhat to do
macOS says the program cannot be opened because the developer cannot be verified.Clear the quarantine flag with xattr -dr com.apple.quarantine as shown above.
The service fails and the journal mentions permissions.The buildspawn user cannot read the program folder or write the home. Move the program to /opt/buildspawn and run chown on the home.
Charts show errors or empty boxes.Install fontconfig and a font package.
Two Buildspawns on one home.Run either the service or a terminal run on one home, never both. Stop one first.
The page does not load from another computer.Check BUILDSPAWN_LISTEN=all and open the port in the firewall.
