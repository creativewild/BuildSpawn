Trusted certificates

Add your company’s root certificates, so that the server and its agents trust your internal Perforce, Git, proxy and artifact servers.

When a server uses HTTPS or TLS, it shows a certificate that proves who it is. A root CA (certificate authority) is the company that signs such certificates. Java, which runs Buildspawn, knows the public root CAs. It does not know your own company’s root CA, so it refuses to connect to a server signed by it, with errors such as PKIX path building failed. This page fixes that.

Buildspawn never changes the cacerts file of the Java it ships with, because an upgrade would replace it. It keeps its own folder of certificates instead.

When to use it

Use it when a build or a plugin fails to reach an internal server because the certificate is not trusted: a Perforce server over SSL, a Git server, a package feed, or a proxy that re-signs traffic. To do the whole job with an example, follow Trust your company’s root CA.

How to set it up

  1. Ask your IT team for the root certificate (a .crt, .cer, .pem, .der or .p7b file) and for its SHA-256 fingerprint (a code like 3F:9A:C1:07:…).
  2. Open Settings › Security › Trusted certificates (/manage/trustedCertificates/). Only administrators see it.
  3. Click Add certificates.
  4. Paste the certificate text, or click Choose file… and pick the file.
  5. Each certificate found appears as a card. Compare its SHA-256 with the one from your IT team. Untick any you do not want.
  6. Click Add 1 certificate (or Add n certificates).
  7. Click Restart the server in the yellow bar, at a time that suits you. Java reads trusted certificates only when it starts.

The page shows Restart needed as long as the certificates on disk differ from what the running server loaded.

The Add certificates dialog

You can paste text that has one or more -----BEGIN CERTIFICATE----- blocks (other text around them is ignored), or choose a file of these types: .pem, .crt, .cer, .der and .p7b (also .p7c). Text (Base64) and binary files both work. A file that holds a whole chain adds every certificate in it. The dialog closes only with Cancel, Esc or the add button. Nothing is added until you press the button.

Each certificate found shows its name, who issued it, its dates and its full SHA-256 fingerprint, with a reminder to compare it with your IT team. It also gets badges:

BadgeMeaningWhat happens
Root CAA certificate authority that signed itself.Ticked, can be added.
Intermediate CAA certificate authority signed by another one.Ticked, can be added.
Not a CA certificateThe certificate of one server, not of an authority. A warning explains that you trust a single server certificate, and that it must be replaced when the server’s certificate changes.Can be added after the warning.
ExpiredThe valid-until date has passed.Not ticked by default. You can still tick it.
Already trusted, skippedIt is already in your added list or is built into Java.Never added twice.

Messages you may see: 1 certificate found or n certificates found; No certificate found. Paste text that starts with -----BEGIN CERTIFICATE----- or choose a certificate file.; and This is a private key. Buildspawn only needs the public certificate; the key was not kept. Buildspawn refuses the whole text if it holds a private key, never keeps it, and clears the box.

Windows certificate store

Shown only when the server runs on Windows. The switch Also trust Windows’ certificate store makes Java trust the roots that Windows trusts. It is for companies whose IT team pushes the root certificate to every computer with group policy. No import is needed. It is off by default.

Agents

The switch Send these to agents sends the added certificates to every agent. The agent adds them to its own trust folder and restarts after its current build, so that it trusts them too. It is on by default. A table lists every agent:

ColumnWhat it shows
Agent, Platform, Agent versionWhich agent, its system and its version.
CertificatesThe state, in the table below.
NoteWhat happens next.
StateMeaning
Up to dateThe agent loaded the same set as the server sent. The note says when it received them.
Waiting for restartThe agent got the certificates but has not restarted. It restarts when it is idle, or after its current build (the note names the build). If it cannot restart by itself, the note says Restart the agent to use them.
Older agentThe agent is too old to take certificates. Update it to 1.9 or later.
OfflineThe agent gets them when it connects.
SendingThe server is sending them now.

With the switch off, Agents keep only their own certificates. The cards have Save and Cancel buttons. Click Save after you change a switch.

The expiry notice

An administrator notice appears on the Settings overview when an added certificate expires within 30 days, or has expired. It names the certificate and links here. Add the new certificate from your IT team before the date.

Where the files are

trust/
  trust.properties       windowsStore=true|false, sendToAgents=true|false
  added/
    <SHA-256>.pem        one certificate
    <SHA-256>.properties who added it, when, and from where (web, launcher or cli)

Agents have the same layout in their work folder (trust/), with one more folder, from-server/, that the server replaces each time it sends. The server and agents read these folders only when they start. A bad or unreadable file is skipped with one warning in the log. It never stops the start.

A worked example

Nightlight Games runs Perforce over SSL with a certificate signed by Nightlight Root CA. Builds fail with PKIX path building failed. The administrator downloads nightlight-root-ca.crt from the IT portal, adds it on this page and checks the fingerprint against the portal. The yellow bar says Restart needed. After a night-time restart the server connects. Four agents are listed as Waiting for restart, and a few minutes later each says Up to date. One old agent says Older agent and is upgraded.

What you see when it runs

  • The yellow bar Restart needed until the server starts again, with a button Restart the server.
  • Agent rows change from Sending to Waiting for restart to Up to date.
  • After the restart, connections to the internal server work and the PKIX errors are gone.

Problems and fixes

ProblemWhat to do
The errors continue after you added the certificate.Restart the server. Java reads the certificates only at start. Do the same for agents (see Waiting for restart).
You added a server certificate and it stopped working later.It was Not a CA certificate. When the server gets a new certificate, add the new one, or add the root that signed it.
An agent says Older agent.Update the agent to 1.9 or later.
An agent says Waiting for restart for a long time.It restarts when idle. If the note says Restart the agent to use them, restart it yourself.
Adding a file says No certificate found.The file is not a certificate. Ask IT for the public certificate, not a key or a .pfx file.
The notice says a certificate expires soon.Get the new one from IT, add it, and remove the old one.
