Running the server

The short guide to choosing a download, starting the server for the first time, and knowing where its port, memory, logs and data are.

Every package except the war includes its own Java. There is a start page in the download folder, START-buildspawn-<version>.html, that shows the steps for each system.

First start

  1. Install and start as described for your system. On Windows, open the app and press Start on Run here, or install the service. On Linux and macOS run buildspawn (or bin/buildspawn), which opens the launch flow.
  2. Open http://localhost:8080/ in a browser. From another computer use the server's name or address instead of localhost.
  3. A setup page asks for the initial admin password. Get it as described below and type it in.
  4. Follow the setup page. See Your first start.

The initial admin password

On a new data folder the server makes a one-time password for the user admin. It is written to secrets\initialAdminPassword inside the data folder, and deleted when you finish the setup page.

Where you run BuildspawnHow to read it
Windows appThe Run here tab shows it under First start: initial admin password, with Copy.
Terminal programThe launch flow shows it (v shows, c copies). Later run buildspawn admin-password (add --copy to use the clipboard). On a Linux package use sudo.
Any systemOpen the file in the data folder.

Ports

PortUse
8080 (default)The web page, the API and the agents. Change it in the settings file (port on Windows, BUILDSPAWN_PORT on Linux and macOS), in the Windows app's Settings tab, or with buildspawn set port=....

The server listens on all network interfaces by default in the settings file. The launch flow suggests This PC only for a try-out. Agents and other people need all. On Windows the setup and the launch flow can add a firewall rule named Buildspawn for the port. On Linux and macOS, open the port yourself.

Arguments

Extra arguments go in the arguments setting (BUILDSPAWN_ARGUMENTS on Linux and macOS), or in Extra arguments in the Windows app. They are added to the command that starts the server. Two you may need:

ArgumentWhat it does
--sessionTimeout=480How long a signed-in browser stays active without use, in minutes. 480 is eight hours.
--prefix=/buildspawnServes Buildspawn under a path, for example http://server:8080/buildspawn/. Use it when a reverse proxy publishes the server below a path. Set the same path in the proxy.

Restart the server after a change.

Memory

The memory setting is the Java heap, used as both the starting and the largest size. When it is empty (Linux, macOS) or not changed (Windows) the server takes a quarter of the computer's memory, between 2 GB and 16 GB. Builds run in their own processes, so they do not use this memory. Raise it when the server is slow with many projects or long histories. Change it in the Windows app's Settings tab, the launch flow, or buildspawn set memory=8g --apply. See Settings files for the Java options.

One data folder, one server

  • The data folder is the home. It holds everything you made. Back it up.
  • Run the server either as the service or by hand on one home, never both. The server keeps a lock file, buildspawn.pid, in the home, and the app and terminal program refuse to start a second one.
  • Upgrade rule: install the new version over or next to the old one and point it at the same home. Take a backup first. Do not run an older version on a home that a newer version has opened. Go back by restoring the backup.
