Step statuses and BUILD_STEP_STATUS

Every step ends with a status. Later steps can read it, so a clean-up step can act differently after a failure.

When to use it

Use the status to print a clear summary at the end of a build, or to do something only after a certain step passed or failed.

The statuses

StatusMeaning
SUCCESSThe step ran and finished well.
FAILUREThe step ran and failed, or could not start.
UNSTABLEThe step ran to its end but made the build unstable, for example because tests failed.
SKIPPEDThe step did not run because of its Execute step setting or a condition.
DISABLEDThe step is switched off.
ABORTEDThe build was stopped while the step ran.

How to read a status in a script

A finished step sets an environment variable named BUILD_STEP_STATUS_ plus its Step ID in capitals. For the ID unit_tests it is BUILD_STEP_STATUS_UNIT_TESTS. The steps after it can read it.

  1. Open the first step and find its Step ID. The list shows it under the step name.
  2. In a later Command Line step on Windows, read the variable:
    if "%BUILD_STEP_STATUS_UNIT_TESTS%"=="FAILURE" echo Tests failed, collecting logs
  3. In PowerShell:
    if ($env:BUILD_STEP_STATUS_UNIT_TESTS -eq "FAILURE") { Write-Host "Tests failed" }
  4. Set the later step to Execute step › Even if some of the previous steps failed. Otherwise it is skipped before it can read anything.

A worked example

The build configuration Engine / Unit Tests has a step with the ID nunit. A last step runs Even if some of the previous steps failed and prints:

echo NUnit step: %BUILD_STEP_STATUS_NUNIT%

What you see when it runs

The console prints NUnit step: FAILURE (or SUCCESS, UNSTABLE and so on). The Build steps card on the build page shows the same result in words: succeeded, failed, unstable, skipped, disabled or stopped.

Problems and fixes

ProblemWhat to do
The variable is emptyThe step you read has not finished yet, or its ID is spelled differently. IDs are lowercase in the editor and capitals in the variable name.
The reading step never runsIt was skipped because an earlier step failed. Set it to run even if previous steps failed.
