Configured build step

The Configured build step is the wrapper around the steps you edit on the Build Steps page. It holds what is the same for every runner: name, ID, on/off switch, when it runs, conditions, retry, outputs and where it runs.

When to use it

You never add this step yourself. Buildspawn wraps a runner in it when the step has any setting that differs from the plain default, such as a name, a condition or a retry. You meet it in settings files and in the API, where a step appears as a Configured build step that holds the real runner. Knowing this helps you read those files.

How to set it up

  1. Open the build configuration and click Settings › Build Steps.
  2. Click Edit on a step, or add a new one.
  3. Change any field in the table below and click Save. Buildspawn wraps the runner if it needs to.

A worked example

You add a Command Line step named Collect crash dumps and set it to run Only if build status is failed. It is now a Configured build step with the Command Line runner inside. A step left at all defaults stays a plain runner, so older settings keep working.

What you see when it runs

The console block is titled [Step 3/5] Collect crash dumps (Command Line): the step name, then the runner. The runner's own output is inside the block.

Problems and fixes

ProblemWhat to do
