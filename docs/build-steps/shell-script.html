Execute shell

Runs a shell script with sh on the build's agent. It is the classic step, kept as it was.

When to use it

Use it on Linux and macOS agents for shell scripts. For new work, Command Line does the same and adds a code editor and container settings.

How to set it up

  1. Open the build configuration and click Settings › Build Steps.
  2. Click Add build step. Type Execute shell in Filter step types if you like, then click the Execute shell tile (group Other).
  3. Type a Step name, for example Build server.
  4. Type the script into Command. Open More options for the unstable exit code.
  5. Optional: set Execute step, Conditions and Retry on failure. See The steps list and the step editor.
  6. Click Save.

Every field

FieldWhat it doesDefaultExample
CommandThe shell script. It runs with the workspace as the current directory. Without a first line such as #!/bin/bash the system-wide shell is used with -ex: every command is printed, and the first command that fails stops the step. A #! line changes the shell or the options, and lets you write in another language. %name% build parameters are put into the text; read secrets from the environment.Empty./build.sh Shipping
Exit code to set build unstable (More options)A shell exit code, from 1 to 255, that makes the build unstable instead of failed. The next steps still run. 0 is ignored.Empty3

A worked example

A Linux agent builds the dedicated server and marks warnings (exit code 3) as unstable. Step name Build server, Command:

#!/bin/bash
set -e
./Scripts/build-server.sh Shipping

Set Exit code to set build unstable to 3.

What you see when it runs

The console block is titled [Step 1/2] Build server (Execute shell). With the default shell options each command is printed with a + in front before it runs. The exit code decides the result.

Problems and fixes

ProblemWhat to do
The script fails on the first small errorThat is -e at work. Start the script with #!/bin/bash and no -e if you want to carry on.
The shell is not found on WindowsThe step looks for sh. Put it on the PATH, or use Command Line.
A secret does not show in the scriptThat is by design. Read the parameter from the environment: $STEAM_KEY.
