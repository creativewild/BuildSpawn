Canvas and palette

Draw a build by dragging blocks onto a canvas and wiring them up. The visual editor shows the same settings as the form, as a graph.

Open a build configuration, click Settings, then Visual editor. The editor and the form edit the same settings: a change in one shows in the other. People who may only view the settings see the graph read-only.

The visual editor is marked Beta on the Settings row. It works on Build configurations and on declarative Pipelines. For a Pipeline the graph is made from the pipeline { } script and written back to it. See Pipeline.

Canvas

The canvas is a grid you can pan and zoom:

  • Drag an empty part of the canvas to move around. Use the mouse wheel, or − and + in the toolbar, to zoom.
  • Fit (the square button beside the zoom) shows the whole graph. The minimap in the corner shows where you are.
  • Auto-layout tidies the blocks into neat rows.
  • Search nodes (press Space) finds a block by name.
  • Drag a block to move it. The layout is saved with the settings, but moving blocks never starts a build.

The legend above the canvas names the wire colours: Run order, Text, Number, Boolean and File.

Palette

The palette on the left lists everything you can add, in groups:

  • Build configuration: the one job-wide block. See The build configuration block.
  • Parameters: configuration parameters, environment variables, system properties, and parameters that ask for text, a choice, yes or no, a password or a file.
  • Build steps: the common runners, such as Command Line, PowerShell, Unity, Unreal and MSBuild. More steps holds every other runner.
  • Flow: Sequence, Branch on condition, Parallel and Fail if.
  • Also sources, dependencies and outputs such as artifacts and notifications.

Drag an item onto the canvas to add it. Type in Search nodes to filter the palette.

Wiring

Blocks connect with wires. Drag from a block's output dot to another block's input dot.

  • Run-order wires (grey) set the order the steps run in: from the build configuration block to the first step, then step to step.
  • Data wires (coloured by type) carry values: a parameter into a step that uses it, or a step's output into a later step. Wires are type-checked when you save.
  • To run steps side by side, wire them through a Parallel block. See Parallel blocks.

Flow blocks shape the build. Sequence runs steps one after another. Branch on condition runs a branch only when a condition is true. Parallel runs sides at the same time; with a Matrix it shows as one card with its axes, and an include row can set where it runs. Fail if fails the build on a condition. See Parallel blocks and Matrix mode.

Problems and Compile preview

Under the canvas two tabs help you check your work before you save:

  • Problems lists what is wrong with the graph, for example a wire of the wrong type, a loop or a missing value. No problems found means it can be saved. A line at the right says when the last check ran and that there are no cycles.
  • Compile preview shows what Save will write, in the words of the forms and in the order of the Build Steps list. Each item is marked new, changed or unchanged since the last save. It also shows the failure conditions, the declared outputs and who reads them, and anything else that changes.

Properties

To change a block's settings:

  1. Right-click the block and choose Open properties, or select it and press Enter.
  2. A large dialog opens with the block's own form: for a step, the same fields as on the Build Steps home, plus its execution settings, retry, outputs and Run on.
  3. Click Save in the dialog. The change is kept in the editor until you save the page.

The side panel button in the toolbar opens a read-only panel beside the graph that shows the selected block. You can resize it; it remembers its width.

Save

The Save button in the toolbar has a small arrow beside it for the other ways to save.

  • Validate checks the graph without saving and lists any problems.
  • Save writes the graph back to the build configuration. The status beside the zoom says No unsaved changes once it is saved.
  • Undo and Redo go back and forward up to 100 changes.
  • Open as form switches to the form view of the same settings.

If someone else saved the same build configuration while you were editing, your save is refused and tells you who saved and when. Reload to get their changes, then make yours again.

Opening the editor and saving with no changes leaves the settings exactly as they were, so it is safe to explore.
