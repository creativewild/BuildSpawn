What is Buildspawn

Buildspawn is a build server. It checks out your code, runs your build steps on your own machines and shows you what happened.

What it does

A build server takes the boring, repeatable work off your team. When someone submits a change, Buildspawn:

  • notices the change in Git or Perforce;
  • picks a free machine (an agent) that can build it;
  • runs your build steps there: compile, cook, test, package, upload;
  • keeps the result: the log, the test results and the files you want to keep (artifacts);
  • shows everyone on the team whether the build passed or failed, and why.

The main ideas

WordWhat it means
ProjectA folder that groups build configurations and other projects, for example Game or Engine. Settings you put on a project, such as parameters or version control connections, pass down to everything inside it.
Build configurationOne kind of build, for example Game / Windows Build. It says where the code comes from, which steps to run, when to start and what to keep. A template is a build configuration others can start from.
BuildOne run of a build configuration, with a number (#1, #2 …), a result, a log and its changes.
StepOne thing a build does: a command line, a PowerShell script, a Unity or Unreal Engine build, a test run, a store upload and so on.
AgentA machine that runs builds. Each agent has one or more executors, so it can run that many builds at once.
PoolA group of agents, for example Windows, Linux or Consoles. You give pools to projects, so builds land on the right machines.
ParameterA named value a build can use, such as CONFIG=Shipping. Secrets are parameters whose value is hidden everywhere.
QueueWhere a build waits until an agent that can run it is free.

Made for game studios

Buildspawn works for any software, but it has extra help for games:

  • Perforce as a first-class version control system: streams, shelves, review status, a workbench page and a Perforce operations build step, next to Git.
  • Unity and Unreal Engine build steps, with the right fields for each engine.
  • Store uploads: build steps for Steam and the Epic Games Store.
  • Agent telemetry, including GPU use, so you can see which build machines are busy or short of disk.
  • Pools with platform icons for Windows, Linux, macOS and consoles, and a Pool Scheduler that moves agents between pools at set times or when urgent builds wait.
  • Parallel blocks and Matrix builds that cook several platforms at once, and resume from the failed step so a two-hour cook does not run again.
  • Personal builds and personal machines: test a shelf, or run a build on your own computer, before anything reaches the depot.

The visual editor

You can set up the steps of a build configuration as a graph: boxes for steps, lines for the order, and a run view that draws a real build over the graph. You can also use plain forms. Both edit the same settings.

What you need

  • One computer for the server: Windows, Linux or macOS. Java is included in every download, so you don't install it yourself.
  • Any number of computers as agents. The agent download also includes Java. The server can run small builds itself while you try things out.
  • A web browser on a desktop or laptop screen. You use Buildspawn through its web pages. There is also a terminal program on every system and, on Windows, a small app to start and stop the server.
