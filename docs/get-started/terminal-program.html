The terminal program

Start the server and watch it live from a terminal.

What it is

buildspawn is a terminal program that comes with every download. It is the same program on Windows, Linux and macOS. It sets up and starts the server, and then shows a live monitor of builds, the queue and agents.

Run buildspawn with nothing after it, and it opens one of two screens:

  • the launch flow, on a first run, when this copy has no settings file and no service yet;
  • the live monitor, every other time.

Start it

DownloadHow to start it
Windows setupOpen a new Windows Terminal and type buildspawn. Setup put it on the PATH.
Windows zipIn the program folder, type .\bin\buildspawn.exe.
Linux and macOS foldersIn the folder, type bin/buildspawn.
Linux packagesType buildspawn. The package put it on the PATH.

On Windows, in the program folder, type bin\buildspawn, not just buildspawn. Windows doesn't tell upper and lower case apart, so plain buildspawn there opens Buildspawn.exe, the app.

The launch flow

The launch flow has five steps. Enter goes forward and Esc goes back.

  1. Home: the folder for jobs, build history and settings.
  2. Port & memory: the web port (8080 by default), whether to listen on the network or this computer only, and the Java memory.
  3. Run as: pick one.
    • Service (recommended): starts at boot, runs without anyone signed in and restarts after a crash. It needs administrator rights once to install it. On macOS it is a LaunchAgent and needs none. Ticks under it: start at boot, open the firewall (Windows only), start now.
    • Portable: runs in this window and stops when you close it. No administrator rights. Good for a try-out.
  4. Admin password: the first-login password. Press v to show it and c to copy it.
  5. Start: a summary. Then it starts the server and switches to the live monitor.

You can save your answers as a preset and use them again on another machine:

buildspawn launch --preset NAME

To open the launch flow again on a copy that is already set up, run buildspawn launch.

The seven views

KeyViewWhat it shows
1OverviewTiles with bars and trends, and the recent builds
2BuildsThe last 24 hours: filter, result chips, group by job. Enter opens the build log.
3QueueEvery waiting item and why it waits
4AgentsState, executors, labels, free disk
5LogsThe server log, the GC log and a build log, with a level filter
6ServiceThe service: start, stop, restart, install, remove, start at boot
7SettingsPort, listen, memory, home, logs, Java options, arguments. Applying restarts the server after asking.

Actions need an API token

Without an API token the monitor is read only. The Service and Settings views still work. But stopping a build (x), cancelling a queue item (c) and taking an agent offline (d) need a token.

  1. In the web interface, open your account menu (top right) and choose Security.
  2. Under API Token, choose Add new token, give it a name and copy it. It is shown only once.
  3. Save a one-line text file that holds your user name and the token as user:token. Keep the file private.
  4. Start the monitor with --token-file PATH, or set BUILDSPAWN_TOKEN_FILE to the file's path.

See API tokens for more.

Commands for scripts

Every view also has a text twin, so you can use the program in scripts. These are the most used commands:

CommandWhat it does
buildspawn statusWhere it is, whether it runs, URL, home, builds, queue, agents. Exit code 0 when running, 3 when stopped.
buildspawn builds --failedThe Builds table as text. Also --running and --limit N.
buildspawn queue / agentsThe Queue and Agents tables
buildspawn logsFollows the log
buildspawn runRuns the server in this terminal until Ctrl + C
buildspawn start / stop / restartThe service when one is installed for this copy, otherwise in the background
buildspawn checkChecks the settings and Java, and prints the Java command
buildspawn certs listLists the trusted certificates you added. certs add FILE, certs remove FINGERPRINT-OR-NAME and certs windows-store on|off change them.
buildspawn set port=8090Changes the settings file. Add --apply to restart afterwards.
buildspawn admin-passwordPrints the initial admin password while it exists. --copy puts it on the clipboard.
buildspawn helpLists everything

The table commands take --json. Useful options for any command: --url URL to watch another server, --view NAME to open on a view, --once to draw one frame as text and exit, --no-color and --theme.

buildspawn --url http://buildserver:8080/ --view queue
buildspawn status --json

The full list is in Terminal program commands.

Good to know

  • The program uses the same settings file, folders and service as the Windows app, so the two never disagree.
  • Installing, removing, starting or stopping the service asks for administrator permission at that moment. On Linux, actions that need root say so and run sudo only after you answer y.
  • Windows Terminal gets colour and unicode symbols. The old console window gets simple ASCII symbols. Set BUILDSPAWN_GLYPHS=unicode to change that.
  • Without a terminal, for example from a scheduled task, buildspawn prints the status instead of opening the monitor.

The agent's terminal screen

Every agent download has its own terminal screen, buildspawn-agent-tui, on every system. It shows the agent's connection, current build, logs, workspaces and machine details. You can pause the agent (it finishes the current build first) or stop it. View 8, Certificates, lists the certificates from the server and the ones added on that machine: add a file, remove one, see its details, switch the Windows certificate store and restart the agent. For machines without a screen, use buildspawn-agent-tui certs list | add FILE | remove FINGERPRINT-OR-NAME | windows-store on|off. On Windows an agent also has a notification-area app with the same status. See Install an agent.
