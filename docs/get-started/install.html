Install the server

Choose the download for your system and get the server running.

Before you start

Get the files from the Buildspawn 1.9.3 release page. Every download includes Java 21 (Eclipse Temurin 21.0.13.1). You don't need to install Java or anything else.

  • Systems: Windows x64, Linux x64 and ARM (any glibc Linux, not Alpine), and macOS on Apple silicon or Intel.
  • Web port: 8080 by default. You can change it in the settings at any time.
  • Memory: on Windows you set the Java memory in the app. On Linux and macOS the default is a quarter of the computer's memory, between 2 GB and 16 GB.
  • Disk: about 620 MB for the program, plus room for build history and artifacts in the data folder.

Buildspawn keeps everything it needs in one data folder, also called the home: jobs, build history and settings. Back it up, and keep it when you upgrade.

Each download has a .sha256 file next to it. Use it to check that the download is complete before you install.

Windows app and setup

Setup is the easiest way to install Buildspawn on a Windows server or build machine.

  1. Run buildspawn-2.589-buildspawn.21-setup.exe.
  2. Follow the steps. Setup installs the program to C:\Program Files\Buildspawn, adds Start menu shortcuts and an entry in Apps & features.
  3. Choose whether to install the Windows service. The service starts with Windows and restarts Buildspawn if it stops. You can also install it later.
  4. Open Buildspawn from the Start menu. This is the Windows app: it starts and stops the server and shows its log. See The Windows app.
  5. Open http://localhost:8080/ in your browser and sign in. See First start and sign-in.

With setup, the settings file is C:\ProgramData\Buildspawn\buildspawn.cfg. Data and logs are in C:\ProgramData\Buildspawn.

Setup also puts the program's bin folder on the PATH, so you can type buildspawn in any new Windows Terminal to open the terminal program.

Upgrade and remove

  • Upgrade: run the newer setup. It stops the service, replaces the program files, keeps your settings and data, and starts the service again.
  • Remove: use Apps & features, or "Uninstall Buildspawn" in the Start menu. It asks before it deletes data. The default keeps it.

Silent install

To install without questions, for example from a script:

buildspawn-2.589-buildspawn.21-setup.exe /S /D=D:\Buildspawn /DATA=D:\BuildspawnData /PORT=8080 /SERVICE=1

/D is the program folder, /DATA the data folder, /PORT the web port and /SERVICE 1 or 0 to install the service or not. Run setup.exe /? to list every switch.

Portable zip

The zip needs no installation and no administrator rights. It is good for a try-out, or for a server you want to keep in one folder.

  1. Unzip buildspawn-2.589-buildspawn.21-windows-x64.zip, for example to D:\Buildspawn.
  2. Open Buildspawn.exe in that folder and click Start.
  3. Open http://localhost:8080/ in your browser.

The settings (buildspawn.cfg), the data and the logs stay next to Buildspawn.exe. A file named portable in the folder tells Buildspawn to work this way.

The zip does not add bin to the PATH. In the program folder, type .\bin\buildspawn.exe, not just buildspawn: Windows doesn't tell upper and lower case apart, so plain buildspawn there opens Buildspawn.exe, the app.

Linux

The tar.gz is a portable folder. Unpack it and start the terminal program:

tar -xzf buildspawn-2.589-buildspawn.21-linux-x64.tar.gz
cd buildspawn-2.589-buildspawn.21-linux-x64
bin/buildspawn

On a first run this opens the launch flow. It asks for the home folder, the port and memory, and how to run:

  • Service: runs under systemd, starts at boot and restarts after a crash.
  • Portable: runs in this terminal and stops when you close it.

Then open http://<this machine>:8080/. In the live monitor, press b to open it when the machine has a desktop.

As a systemd service

Choose Service in the launch flow, or run:

sudo bin/buildspawn install-service

This creates a system user buildspawn with no login, writes /etc/systemd/system/buildspawn.service, enables it at boot and starts it now.

  • Put the folder somewhere the buildspawn user can read, such as /opt/buildspawn. A folder inside your home directory usually isn't readable by it, and install-service checks this.
  • Read the log with journalctl -u buildspawn -f, or in view 5 of the monitor.
  • Remove the service with sudo bin/buildspawn uninstall-service. It keeps the data, the logs and the settings.
  • Builds run as the buildspawn user, so the tools and files they need must be readable by that user.

In this folder, the settings file is buildspawn.conf, the home is data/ and the logs are in logs/.

Install fontconfig and a font, or the charts in the web interface can't be drawn.

Debian, Ubuntu and RHEL packages

The packages are for Linux x86-64. They install to /opt/buildspawn, put buildspawn on the PATH, and enable and start the service right away.

Debian and Ubuntu:

sudo apt install ./buildspawn_2.589-buildspawn.21_amd64.deb

RHEL, Rocky and Fedora:

sudo dnf install ./buildspawn-2.589-buildspawn.21.x86_64.rpm

There is nothing to start. Open the monitor, or get the first-login password:

buildspawn
sudo buildspawn admin-password
WhatWhere
Program/opt/buildspawn
Settings/etc/default/buildspawn (deb) or /etc/sysconfig/buildspawn (rpm)
Home (jobs, builds)/var/lib/buildspawn
Logs/var/log/buildspawn and journalctl -u buildspawn

Start, stop and restart with sudo buildspawn start|stop|restart, or with systemctl. To upgrade, install the newer package over the old one. Your settings and home are kept.

macOS

The macOS package isn't signed by Apple, so macOS blocks it after a browser download. Clear the block once, in Terminal, before the first start (the second line below). On an Intel Mac, use the macos-x64 file.

tar -xzf buildspawn-2.589-buildspawn.21-macos-aarch64.tar.gz
xattr -dr com.apple.quarantine buildspawn-2.589-buildspawn.21-macos-aarch64
cd buildspawn-2.589-buildspawn.21-macos-aarch64
bin/buildspawn
  1. The launch flow opens.
  2. Pick Service to start Buildspawn whenever you log in (a LaunchAgent; no sudo), or Portable to run it in this window.
  3. Open http://<this Mac>:8080/, or press b in the monitor.
  • The service runs as you, so builds can use your Xcode, keychain and tools. It runs while you are logged in. For a build Mac that must come back after a restart, turn on automatic login.
  • The first start may ask to accept incoming network connections. Allow it.
  • The log is logs/buildspawn.log, or view 5 of the monitor.
  • If you move the folder, run bin/buildspawn install-service again.

The server alone (.war)

If you already run Java 21 and want to manage it yourself, use buildspawn-2.589-buildspawn.21.war. It holds the whole server, with every bundled plugin, but no launcher, service or Java.

java -jar buildspawn-2.589-buildspawn.21.war --httpPort=8080

Started like this, the server keeps its home in a folder in your user profile, and you choose the Java memory and options yourself. The other downloads set the home, the port, the memory and the recommended Java options for you, so use them unless you have a reason not to.

Check the download

Each file has a .sha256 file next to it. It holds the file's fingerprint. Compare it with the fingerprint of your copy.

# Windows, PowerShell
Get-FileHash .uildspawn-2.589-buildspawn.21-setup.exe -Algorithm SHA256

# Linux
sha256sum -c buildspawn-2.589-buildspawn.21-linux-x64.tar.gz.sha256

# macOS
shasum -a 256 -c buildspawn-2.589-buildspawn.21-macos-aarch64.tar.gz.sha256

If the two fingerprints differ, download the file again.

Upgrade from an older version

Install 1.9.3 over 1.8, 1.9, 1.9.1 or 1.9.2. Your settings, build configurations, history and permissions stay as they are. Use the same kind of download as before: run the newer setup, or unpack the newer folder and point it at the same data folder, or install the newer package over the old one. Back up the data folder first. See Backups and upgrades.

Agents from 1.9 on receive the server's trusted certificates. Download the agent again from Agents › Install agents to update an older one. See Install an agent.
