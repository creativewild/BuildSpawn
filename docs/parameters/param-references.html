Parameter references

Write %name% in a step to put a value there when the build runs.

When to use them

Use a reference whenever a runner field or a script needs a value you keep in a parameter, a value the build knows (such as the changelist), or a value from another build in the chain.

How to use them

  1. Open the step: Settings › Build steps, then the step.
  2. Type % in the script editor. It lists the parameters of the build. Pick one, or type the name.
  3. Save. At run time, Buildspawn replaces each reference with its value.

Every kind of reference

ReferenceWhat it isExample
%NAME%A build parameter (configuration kind). Also a value an earlier step set with setParameter; the latest value wins.%CONFIG%
%env.NAME%An environment parameter. In a batch file it becomes %NAME%, which the batch file reads from the environment itself.%env.UE_SDK_ROOT%
%system.name%A system property.%system.build.flavour%
%build.*%A value the build knows: number, counter, changelist, branch, who started it, checkout folder. See Build values.%build.vcs.number%
%vcsroot.*%A property of a version control root: %vcsroot.url% with one root, %vcsroot.<id>.url% with several.%vcsroot.branch%
%agent.*%A parameter of the agent. See Agent parameters.%agent.name%
%tool.<id>%The path of a tool on the agent. Not allowed in a container.%tool.msbuild%
%dep.<ID>.<name>%A value of a dependency build in this chain. See Build chains.%dep.Game_Cook.build.number%
%vault:path!/key%A secret fetched from HashiCorp Vault when the build starts. See Vault.%vault:secret/data/game!/key%
%reverse.dep.…%Not a reference but a parameter name that sends a value to a dependency. See Build chains.reverse.dep.*.config
%%One percent sign, where something else was replaced.50%%

Rules

  • One pass from left to right. A value is never read again, so %other% inside a value stays as written.
  • A reference to a name Buildspawn does not know stays as written. A name such as %PATH% is left for the shell.
  • A secret is never written into a script. A reference to a password parameter fails the step, and the message names the environment variable to read instead. In a batch file the reference is left for cmd.
  • A value that someone who may not configure the build configuration typed is not written into code. The step fails and names the parameter. A value at its default is always allowed.
  • In a Windows batch script a value has each percent sign doubled, so cmd reads it once.

A worked example

powershell -File Build\ci.ps1 -Stage package -Version %version% -Changelist %build.vcs.number% -Agent %agent.name%

What you see when it runs

The log shows the command with the values filled in. Secrets show as dots.

Problems and fixes

ProblemWhat to do
The reference stays as writtenThe name is wrong or the value does not exist yet (for example a %dep.…% of a build that was not in the chain).
The step fails with a secret messageRead the secret from the environment variable the message names.
The step fails with "changed value"Someone without Configure permission typed a value that is not the default. Ask a person who may configure the build configuration to run it.
