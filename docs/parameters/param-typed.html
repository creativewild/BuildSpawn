Parameter with a value type

The parameter you create with Add parameter: one name, one kind, and a value type that decides what people can enter.

When to use it

Use it for every new parameter. Text, Checkbox, Password, Select and Remote cover the old String, Boolean, Password and Choice parameters, and add rules, labels and values fetched from a vault.

How to set it up

  1. Open the build configuration and go to Settings › Parameters.
  2. Click Add parameter.
  3. Type the Name and choose the Kind.
  4. Choose the Value type: Text, Checkbox, Password, Select or Remote. The fields below change with it.
  5. Fill in the value and the rules. Optional: open Customize the run dialog.
  6. Click Save. The Parameters tab saves as you work, so there is no other Save button.

A worked example

The Windows Build asks for the build type. Add a parameter named CONFIG, kind Configuration parameter, value type Select, items Development, Shipping, Debug build => Debug. A step then runs:

powershell -File Build\ci.ps1 -Stage compile -Config %CONFIG%

What you see when it runs

The Parameters tab lists the row with its kind and Asked when the build runs. In the Run dialog people see a list. A value that breaks the rules is refused, so the build does not start.

Problems and fixes

ProblemWhat to do
The name is refusedNames are unique in a build configuration.
The Regex message appears in the Run dialogThe value did not match the whole pattern. You do not need anchors: the whole value must match.
Remote is missing from Value typeNo remote source is installed on this server. See Vault.
