Connect an agent

An agent connects to the server from its own machine. This page explains how that connection works, the settings file that controls it, and the options for WebSocket, TCP, proxies and Java.

When to use it

Read this page when an agent will not connect, when it must pass a company proxy or firewall, when you need to give the agent more memory, or when you want to know what is in conf/buildspawn-agent.properties.

How the connection works

  • The agent calls the server. This is the inbound agent (Launch agent by connecting it to the controller). The server never needs to reach the agent, so the agent can sit behind a router or a company firewall. It only needs to reach the server's address.
  • The agent starts with the server address and one of two ways to prove who it is: a secret (an agent made with New Node), or a registration request that an administrator approves (see Install an agent). After approval, the secret is written into the settings file for you.
  • The connection is a WebSocket by default. A WebSocket is a normal web connection on the same address and port as the Buildspawn pages. No extra port is needed.
  • If the connection drops, the agent tries again by itself. The tray app and the terminal program show the reason in their Connection log.

WebSocket or TCP

WebSocketTCP
HowUses the server's web address and port.A separate port on the server for agents (Settings › Security, TCP port for inbound agents).
DefaultYes.No. Used only when you turn WebSocket off.
Firewalls and proxiesWorks wherever the web pages work, if the proxy allows WebSocket.Needs the extra port to be open.
Turn it off with—webSocket=false in the settings file, or leave out -webSocket on the command line.

When the server has the TCP port turned off, an agent that asks for TCP switches to WebSocket by itself. To forbid that switch, set webSocketFallback=false in the settings file, or add -noWebSocketFallback to a command-line agent. Then an agent that cannot use TCP simply fails, and says why.

The agent page on the server, Connect the agent, shows a notice when the TCP port is off (The TCP port is disabled so TCP agents may not be connected. You may still use WebSocket agents.) and the command with -webSocket in it. See Security settings.

The settings file

Every agent folder holds conf/buildspawn-agent.properties. It is a plain text file with one key=value per line. Lines that start with # are comments. Keep it private: it holds the agent's secret. The install scripts lock it to the service account.

The agent also writes two keys of its own while it waits for approval, registrationKey and registrationId. Leave them alone.

The tray app and the terminal program edit serverUrl, name, workDir, javaOptions, proxy and webSocket for you. A change applies after the agent restarts.

Registration token

An agent that you did not create with New Node asks to join and waits under the Unauthorized tab until an administrator approves it. To control who may even ask, an administrator can require a token on the Agent registration page: turn on Require a registration token. The token has Show, Hide, Copy and Regenerate.

  1. Open Settings › Agent registration (or Install agents › Agent registration on the Agents page).
  2. Under Registration token, tick Require a registration token, click Copy.
  3. On the agent machine, put registrationToken=THE-TOKEN in the settings file, or run install-service --token THE-TOKEN, or run-agent --token THE-TOKEN.

Without the right token the server refuses the request (The registration token is missing or wrong.) and lists nothing. Regenerate makes a new token. Agents that use the old token are refused from then on. Agents that are already approved, and agents waiting under Unauthorized, are not removed. The token guards who may ask, not what an approved agent may do.

Command-line agent

Instead of the zip you can run the bare agent.jar, for containers or other custom setups. It needs Java 17 or later. On the agent's page, Or connect with a command shows the command with your server's address, the agent's name and its secret (hidden until you click Show secret; Copy copies the full command):

curl -sO https://buildspawn.studio.example/jnlpJars/agent.jar
java -jar agent.jar -url https://buildspawn.studio.example/ -secret SECRET -name "win-build-04" -webSocket -workDir "D:/agent-work"

On PowerShell use curl.exe, not curl. Remove -webSocket to use TCP. Useful options:

OptionWhat it does
-url URL, -name NAME, -secret SECRETServer, agent name and secret.
-webSocketConnect over WebSocket.
-noWebSocketFallbackDo not switch to WebSocket by itself when the server's TCP port is off.
-webSocketHeader NAME=VALUEAdd a header to the WebSocket request, for a reverse proxy that needs one. Repeat it for several headers.
-proxyCredentials USER:PASSSign in to a web proxy.
-tunnel HOST:PORTReach the TCP port through a tunnel.
-workDir DIRThe work folder.
-cert FILETrust the server's certificate from a file. See Trusted certificates.

Run java -jar agent.jar -help for the full list.

A worked example

The studio's build machines sit behind a proxy and the Java heap must be bigger.

  1. Open C:\buildspawn-agent\conf\buildspawn-agent.properties in a text editor.
  2. Add proxy=proxy.studio.example:3128 and javaOptions=-Xmx6g.
  3. From an administrator prompt in that folder, run install-service.bat. It writes the new Java options into the service definition and starts the service again.
  4. Watch the Connection log in the tray app. It shows Connected.

What you see when it runs

  • The first lines in the log: Starting Buildspawn agent 'win-build-04' for https://…/.
  • A self-registering agent prints Registered agent 'win-build-04' and waits. After approval: Agent authorized as 'win-build-04'. Configuration saved.
  • On the Agents page the agent turns Idle. Its connection log says protocol WebSocket.

Problems and fixes

ProblemWhat to do
serverUrl is not setFill in serverUrl or pass --url.
Cannot reach … retryingThe machine cannot open the server's address. Test it in a browser. Check the firewall and the proxy key.
Registration refused: agent name 'x' is already in useChoose another name with --name.
Agent rejected by the administratorAn administrator pressed Reject. Ask why, then start again with another name. Rejected agents are listed for 30 days.
The registration token is missing or wrong.Copy the current token from the Agent registration page.
Secret rejected by the serverThe agent was removed, or its secret was replaced. Download a new zip for it.
Works with TCP, not through a proxy.Use WebSocket, and make sure the proxy lets WebSocket through. Add -webSocketHeader if the proxy needs a header.
