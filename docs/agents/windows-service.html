Agent service scripts

A service starts the agent at boot, restarts it when it stops and keeps it running after you sign out. This page covers the Windows service scripts and the matching scripts for Linux and macOS.

When to use it

Use a service on every build machine that nobody signs in to. Run the agent in a window (run-agent) only to try it, or on a personal computer where the owner's tray app starts it.

The scripts

All scripts sit in the agent folder, for example C:\buildspawn-agent\.

Script (Windows)What it does
install-service.batInstalls the Buildspawn Agent service and starts it. Needs an administrator prompt.
uninstall-service.batStops and removes the service. Needs an administrator prompt.
stop-agent.batStops the service (sc.exe stop buildspawn-agent). Run it as administrator.
run-agent.batRuns the agent in the window, in the foreground. Closing the window stops it.
Script (Linux and macOS)What it does
install-service.shLinux: writes /etc/systemd/system/buildspawn-agent.service, then enables and starts it. Needs sudo. macOS: with sudo installs a LaunchDaemon (starts at boot); as yourself installs a LaunchAgent (starts when you sign in). The name is com.buildspawn.agent.
uninstall-service.shStops and removes the service.
stop-agent.shStops the service.
run-agent.shRuns the agent in the foreground. Press Ctrl + C to stop.

OptionWhat it doesSystems

How to install the service

  1. Unzip the agent download (see Install an agent).
  2. Open an administrator command prompt in the agent folder. On Linux and macOS, use a terminal with sudo.
  3. Run: 
    install-service.bat --url https://buildspawn.example.com/ --name win-build-04
    Leave out the options when you downloaded the zip made for one agent (New Node). It already holds the address and the secret.
  4. The script says Service "Buildspawn Agent" installed and started. Logs: C:\buildspawn-agent\logs.

What the Windows script does, in order:

  1. Checks that it runs as administrator.
  2. Finds Java: the java folder in the agent folder first, then JAVA_HOME, then the search path. Java 17 or later.
  3. Writes the options you gave into conf\buildspawn-agent.properties and stops with an error if serverUrl is empty.
  4. Locks the settings file so that only the system account and administrators can read it. It holds the agent's secret.
  5. Writes bin\buildspawn-agent-service.xml with the Java it found and your javaOptions. The secret is not in it.
  6. Registers the service with WinSW, a small open-source service wrapper (MIT licence, see bin\LICENSE-WinSW.txt), and starts it.

The service is set to start automatically. If the agent stops, it restarts after 10 seconds, then 30, then 60. The failure count resets after an hour.

Run install-service again

You can run install-service.bat again on a machine where the service already exists. It stops the old service, removes it and installs it again from the folder you are in. Do this:

  • after you upgrade the agent files (see Upgrade agents);
  • after you move or replace the agent folder, because the service points at the old folder;
  • after you change javaOptions, because the Windows service definition holds the Java options;
  • when the service does not start and logs is empty.

The script then says Service "Buildspawn Agent" installed again from C:\buildspawn-agent\ and started. If it says could not remove the old service definition, close the Services window (services.msc) and try again.

The same applies to Linux and macOS: run install-service.sh again after you change javaOptions, because the installed definition holds the options.

Upgrade an agent without registering it again

The agent's registration lives in conf\buildspawn-agent.properties (the name and the secret). As long as you keep that file, the agent stays the same agent on the server, in the same pool and with the same history. See Upgrade agents for the steps.

A worked example

A studio moves its build agents from C:\buildspawn-agent to D:\agents\win-build-02 because the C: drive is small.

  1. On win-build-02, run stop-agent.bat as administrator.
  2. Move the whole folder, with conf and work, to D:\agents\win-build-02.
  3. Open an administrator prompt in the new folder and run install-service.bat. It replaces the old registration with one that points at the new folder.
  4. The agent comes back online under the same name and pool.

What you see when it runs

  • In services.msc: Buildspawn Agent, Status Running, Startup type Automatic.
  • On the server's Agents page: the agent turns Idle within seconds.
  • On Linux, systemctl status buildspawn-agent shows active (running). The unit restarts the agent after 10 seconds if it stops.

Problems and fixes

ProblemWhat to do
run this from an administrator promptOpen the prompt with Run as administrator.
serverUrl is not setPass --url or set serverUrl in conf\buildspawn-agent.properties.
Java 17 or newer is requiredUse the download with Java inside, or set JAVA_HOME.
The service does not start and logs is empty.Check that bin\buildspawn-agent-service.xml exists, then run install-service.bat again.

ERROR: run with sudo (Linux)Run sudo ./install-service.sh.
