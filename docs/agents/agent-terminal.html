Agent terminal program

The agent terminal program, buildspawn-agent-tui, shows what an agent is doing in a console window. It works on Windows, Linux and macOS, over a remote shell too, and it lets you pause the agent, read logs, clean work folders and change settings.

When to use it

Use it on a build machine that you reach over SSH or remote desktop, on a machine with no desktop, or when you prefer the keyboard. On Windows it shows the same information as the tray app. Like the tray app, it talks to the agent on the same machine, so it keeps working when the server cannot be reached.

How to set it up

It is already in every agent download, in the bin folder of the agent folder. Nothing to install.

  1. Open a terminal on the agent machine. On a service machine, run it as the account that runs the agent, or as an administrator or with sudo, so that it may control the agent.
  2. Go to the agent folder and start the program: 
    # Linux and macOS
cd /opt/buildspawn-agent
./bin/buildspawn-agent-tui

# Windows
cd C:\buildspawn-agent
bin\buildspawn-agent-tui.exe
  3. Press 1 to 8 to change view. Press ? for help and q to leave.

Leaving the program does not stop the agent. The screen says Terminal closed. The agent is still running. Run buildspawn-agent-tui to come back.

The program needs a real terminal. With output sent to a file or a pipe, use --once.

buildspawn-agent-tui --once --view 3 --cols 100

The keys

KeyWhat it does
1 to 8Switch view.
pPause or resume. The running build finishes, and no new build starts while paused.
rReconnect to the server now. If the agent is not running, look for it again.
bOpen this agent's page in the browser.
?Help with every key.
qQuit this screen (the agent keeps running). Asks Quit or Stay.
Ctrl + CQuit at once.
EscClose a dialog or cancel an edit.

The screen looks again every 2 seconds. When the agent cannot be reached, the data is greyed out and marked last known.

The eight views

1 Overview

  • Current build: job and number, step, elapsed time, a progress bar and the last log lines. No build is running. when idle.
  • This machine: CPU, RAM and free disk of the work folder, with bars that turn yellow and red.
  • Agent version, Java version and Builds at a time.
  • On a personal machine: Personal agent and the owner.

2 Builds

The current build, Waiting for this agent (n) with the reason (not on a personal machine) and the recent builds with result, duration and time.

KeyWhat it does
↑ ↓Pick a build.
EnterOpen the build's log in the browser.
xStop the running build, after you confirm.
sPersonal machines only: copy a share link for the selected build.

On a personal machine the view says Only your builds are shown. Other people can't see them unless you share a link.

3 Connection log

Every connect, disconnect and reconnect with the reason in plain words and a summary such as 3 drops today, longest offline 4 min. No events yet. when empty.

4 Work folders

The size of each build configuration's folder, and the total. c cleans the selected folder and a cleans all of them, each after a confirmation. A folder that a build uses cannot be cleaned.

5 Service

Shows the service that keeps the agent running: a Windows service, buildspawn-agent with systemd on Linux, or com.buildspawn.agent with launchd on macOS. It shows whether it is installed, running, its start type and account. Keys: s start, x stop, t restart, i install, u remove. Each asks to confirm. Stop, restart and remove warn that A running build will be stopped. Install and remove run the scripts described in Windows service. If you lack rights, the screen says Windows says access is denied. or Start this screen from a terminal opened as administrator.

6 Settings

FieldKey in conf/buildspawn-agent.properties
Server addressserverUrl
Agent namename
Work folderworkDir
Java memory (for example -Xmx8g)javaOptions
Proxyproxy
Use WebSocketwebSocket

↑ ↓ pick a field, Enter edits a text field, Space switches a yes/no field, s saves and v reverts. Save asks Restart now, Later or Cancel. The agent uses the new settings after a restart. When you change javaOptions and the agent runs as a service, the screen reminds you to run install-service again. The secret is kept as it is and never shown.

7 Agent log

The agent's own log. l cycles the level; a shows all lines, w warnings only and e errors only. f follows new lines. ↑ ↓ PgUp PgDn scroll.

8 Certificates

The certificates the agent trusts: from the server (read only) and added on this machine. Keys: a add a certificate file, d remove, Enter details with the SHA-256 fingerprint, w switch also trust the Windows certificate store (Windows only) and t restart the agent so that it uses the changes. See Trusted certificates.

The certs command

For machines with no screen, change the certificates from the command line. The command works with the agent folder directly, so the agent need not be running.

buildspawn-agent-tui certs list
buildspawn-agent-tui certs add company-root.pem
buildspawn-agent-tui certs remove 3F:9A:21
buildspawn-agent-tui certs windows-store on
CommandWhat it does
certs listLists the certificates from the server and the ones added here, the Windows store setting, and whether the agent needs a restart.
certs add FILEAdds the certificates in a .pem, .crt, .cer, .der, .p7b or .p7c file. - reads text from standard input. It shows each certificate first and asks. A private key is refused: only the public certificate is needed. Expired certificates are skipped.
certs remove FINGERPRINT-OR-NAMERemoves one certificate added here. The fingerprint may be just the start, with or without colons. Certificates from the server cannot be removed here.
certs windows-store on|offAlso trust what the Windows certificate store trusts. Windows only.
OptionWhat it does
--yesDo not ask.
--include-expiredWith add: also add expired certificates.
--home FOLDERThe agent folder.

Changes take effect when the agent starts again.

A worked example

A Linux build machine, ubuntu-build-03, sits in a rack and is reached over SSH. Builds on it fail with an out-of-disk error.

  1. Log in over SSH and run /opt/buildspawn-agent/bin/buildspawn-agent-tui.
  2. The Overview shows Disk free in red.
  3. Press p to pause the agent, so no new build starts.
  4. Press 4. The biggest folder is Game_Linux-Build. Select it and press c, then confirm.
  5. Press p again to resume.

What you see when it runs

  • A title line with the agent's name, its connection state and the server address.
  • A tab line with the eight views. The open view is highlighted.
  • The body of the view, and at the bottom a line with the keys that work in that view.
  • Messages such as Saved. Settings apply after a restart. above the key line.

Problems and fixes

ProblemWhat to do
This needs a terminal.You ran it with output sent to a file. Use --once.
The agent isn't running.Start it (run-agent, or the service), then press r.
This agent runs as another account.Start the program as an administrator, with sudo, or as the account that runs the agent.
No view 8 on an older agent.The agent files are older than 1.9.2. See Upgrade agents.
