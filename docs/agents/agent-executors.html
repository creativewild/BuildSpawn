Builds at a time (executors)

An executor is one slot on an agent that runs one build. The number of executors is the number of builds that the agent runs at the same time.

When to use it

Set it when you add an agent, and change it when you see builds waiting while agents are half idle, or when builds slow each other down because the machine is overloaded.

How to set it up

  1. Open Agents, click the agent, then Configure.
  2. In General, set Number of executors.
  3. Click Save. The change applies at once. Running builds are not stopped.

Every field

FieldWhat it doesDefaultExample
Number of executorsThe most builds that run on this agent at the same time. An agent needs at least 1. A good first value is the number of CPU cores. A higher value raises the total work done, because one build may wait for the disk while another uses the CPU, but each build takes longer.12

Other places that show or set it:

PlaceWhat it does
Agents listThe Status column says how many executors are free. The header counts busy executors of all executors. An opened row lists each busy executor with its build.
Pool page and Pools tabShow the executors of each pool.
My machinesThe owner of a personal machine sets Builds at a time there. Default 1.
Tray app, terminal programShow Builds at a time read only. Set it on the server.
Agent's Load StatisticsA chart of busy and total executors over time.
The built-in nodeSet its executors to 0 so that it runs no builds itself. It still runs the light "flyweight" jobs, such as the top-level part of a pipeline.

How to choose a number

  • Devkits and consoles: 1. The devkit can run one thing at a time.
  • Unreal Engine or Unity builds: usually 1 or 2. Each build uses many cores and a lot of memory, and two builds of the same project need two workspaces on disk.
  • Small tests and scripts: up to the number of cores.
  • Personal machine: 1, so builds do not slow your own work.

Every executor needs its own workspace folder, so more executors also use more disk. For a game project of 200 GB, 2 executors need about 400 GB.

A worked example

The agent win-build-02 has 16 cores, 64 GB of memory and a 2 TB disk. It runs the studio's quick Unit tests build configuration and the heavy Windows Client build.

  1. Set Number of executors to 2.
  2. Click Save.
  3. Start a client build and a unit-test build together.

What you see when it runs

  • On the Agents page, win-build-02 shows Building and 0 free while both run. With one running, it shows 1 free and the pool still counts the agent as available.
  • The third build waits in the queue with the reason that all executors are busy, until one is free.

Problems and fixes

ProblemWhat to do
Builds are very slow since you raised the number.The machine is overloaded. Lower it, and check CPU and memory in Telemetry.
The disk fills up.Each executor has its own workspace. Lower the number or clean workspaces (the tray app has Work folders).
The form refuses 0 for an agent.An agent needs 1 or more. To stop builds, use Mark offline. Only the built-in node may have 0.
Two builds of one build configuration cannot run at once.The build configuration may have Execute concurrent builds off. That is a setting of the build configuration, not of the agent.
