Windows tray app

The tray app is a small Windows program that sits next to the clock and shows what the agent on this machine is doing. You can pause the agent, read its logs, clean work folders and change its settings from it.

When to use it

Use the tray app on any Windows machine that runs a Buildspawn agent, whether it is a build machine, a devkit host or your own computer (see Personal agents). It works with the agent running as a Windows service and with an agent that the app starts itself. It talks to the agent through a local connection on the same machine, so it works even when the server cannot be reached. It then shows the last data it knows.

How to set it up

Every Windows agent download already holds the app. You do not install it separately.

  1. Unzip the agent download, for example into C:\buildspawn-agent\.
  2. Open the bin folder and double-click Buildspawn Agent.exe. The icon appears in the notification area (click the small arrow next to the clock if it is hidden).
  3. If the agent is not running yet, right-click the icon and choose Start the agent. The app starts the agent in the background and hides its window.
  4. To start the app every time you sign in to Windows, open the Settings tab and tick Open this app when I sign in to Windows, then click Save.

The app finds the agent folder by itself: the folder above the bin folder it runs from. To point it at another agent folder, start it with --home "D:\other-agent".

A second start of the app does not open a second copy. It brings the first window to the front.

The tray icon

The icon changes colour with the state of the agent. Hover over it to see a short line of text.

IconMeaningTooltip text
GreenConnected and idle.Agent name · Idle · Connected
Blue, pulsingA build is running.Build name · time so far
AmberPaused. The running build finishes, then no new builds start.Paused · finishes the current build
RedOffline, connecting, or the agent is not running.Offline · reconnecting in 12 s

The app also shows short pop-up messages: Agent disconnected, Agent reconnected, and one for each build that finishes (passed, failed or stopped).

The tray menu

Right-click the icon. A left click opens the window.

ItemWhat it does
Start the agentStarts the agent. Shown only when it is not running.

Open (bold)Opens the window.
Pause / ResumePause: the build that runs now finishes, and no new build starts here. Resume: take builds again. The server applies it within a few seconds, and it is remembered while the agent is offline.

Restart agentStops and starts the agent. A running build is stopped.
ExitCloses the app. It asks whether the agent keeps running. Keep running leaves the agent alone. Stop agent stops it (a service is stopped after Windows asks for permission). Cancel keeps the app open.

The window closes to the tray when you click the close button or press Esc. Only Exit ends the app.

Every tab

The window has eight tabs. The title bar shows the agent's name.

Status

The first look at the machine.

FieldWhat it shows

ServerThe server address the agent uses.
Last contactHow long ago the server was last heard from.
Reconnects todayHow many times the connection came back since midnight.
Current buildThe running build, a progress bar against its usual time, the current step and the time so far. (+2 more) when several builds run.
CPU, RAM, DiskBars with the percent used on this machine. Disk is the drive of the work folder.
Button at the bottomPause, Resume, Start the agent or Open as administrator, depending on the state.

Builds

  • Current: the build running now with its time. Stop build asks Stop …? and stops it.
  • Waiting (n): builds in the queue for this agent, with a Why column. Hidden on a personal machine.
  • Recent (n): columns Build, Result and Finished. Press Enter or double-click a build to open its log in the browser. On a personal machine only the owner's builds are listed, and Share copies a link that lets other people read the selected build.

Connection log

A line on top counts the drops today and the longest time offline, for example 3 drops today · longest time offline 4 min. The list has Time, Event (Connected, Disconnected, Reconnecting) and Reason in plain words, such as Network lost (the PC went to sleep?), Ping not answered for 60 s or Secret rejected by the server. The last 1000 events are kept, even across restarts.

Agent log

The agent's own log, newest line first. Buttons All, Warnings and Errors filter it. Open log folder opens the folder in Windows Explorer.

Work folders

One row for each build configuration's folder in the work folder, with its Size and a State (In use while a build uses it). Clean deletes the selected folder after you confirm. Clean all deletes every folder, and the next builds start from scratch. A folder in use cannot be cleaned. The line at the bottom shows the Total size.

Each one asks you to confirm, then Windows asks for administrator permission. Install and Remove run install-service.bat and uninstall-service.bat from the agent folder (see Windows service).

Certificates

The certificates this agent trusts, in two lists. See Trusted certificates for the server side.

  • Also trust Windows' certificate store: tick it to also trust everything Windows trusts. This helps behind a company proxy.
  • From the server (n): certificates the server sent when the agent connected. They cannot be removed here. A note says when they were last received.
  • Added on this machine (n): certificates you added. Add… takes a .pem, .crt, .cer, .der, .p7b or .p7c file and shows each certificate first. Remove asks, then removes the selected one. View… shows the details and the SHA-256 fingerprint.
  • A band says The agent restarts to use them after the current build. with Restart agent now.

The agent keeps these in work\trust, so they survive an upgrade of the agent files.

Click Save. The note under the form says Saved in conf\buildspawn-agent.properties. The secret is not shown here. If the file belongs to the service account, Windows asks for administrator permission first. After saving, the app asks Restart now or Later. A changed Java memory and options also needs install-service.bat to be run again when the agent runs as a service. See Connect an agent for what each key means.

A worked example

A level designer's PC at the studio runs a personal agent named dana-pc. Dana is about to play-test and needs the CPU.

  1. Dana right-clicks the tray icon and chooses Pause. The icon turns amber.
  2. The build that was running finishes. No new build starts on dana-pc.
  3. After the session Dana right-clicks the icon and chooses Resume. The icon turns green.

What you see when it runs

  • A pop-up Agent disconnected when the connection drops, and Agent reconnected when it returns.
  • The window refreshes by itself every 2 seconds.
  • The server's Agents page shows the pause too: the agent's row says it is paused.

Log files

FileWhat is in it
logs\run-agent.logEverything the agent prints when the app starts it. If the agent stops right at the start, read this file first.
logs\tray.logUnexpected errors of the tray app itself. If that folder cannot be written, the file buildspawn-agent-tray.log goes in the Windows temp folder.

When the agent runs as a service, its output goes to the service logs in the same logs folder (see Windows service).

Problems and fixes

ProblemWhat to do
The status says This agent runs as another account.The service runs as the system account. Choose Open as administrator from the tray menu.
Start the agent does nothing.Read logs\run-agent.log. A missing serverUrl, or Java that is too old, is written there.
The icon is red but the server is fine.Open Connection log and read the reason. Secret rejected by the server means the agent's secret is out of date.
The Certificates tab is missing.The agent files are older than 1.9.2. Upgrade them (see Upgrade agents).
The app does not start on an old download.Download the agent again. The app in 1.9.2 and later starts on every Windows machine where earlier copies failed.
