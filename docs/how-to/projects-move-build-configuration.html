Move a build configuration

Move a build configuration to another project and know what will change before it does.

The studio moves Windows Build from Skyforge to Skyforge/Main. It keeps its builds, settings and ID.

Before you start

  • The Configure permission on the build configuration and the Create permission on the destination.
  • No build of it is running.

Steps

Move it

  1. Open the build configuration and click Move.
  2. Under Move to choose Skyforge » Main.
  3. Click Move.
  4. If the page lists problems, read them. Each one is a setting that will change because the new project passes down other things. Click Move anyway only if that is fine.

Fix what changed

  1. Open Settings › Parameters and check the Defined in column.
  2. Add the parameters it lost to the new project, or to the build configuration.
  3. Open More › Dependencies and check that the dependencies still point to the right build configurations.

Check it worked

  1. The build configuration shows in the new project in the tree. Its ID is unchanged.
  2. The old address no longer works. The address /buildConfiguration/<id> still does.
  3. Run it once.

Troubleshooting

ProblemWhat to do
Move is refused: a build is runningStop it or wait, then move.
Move is refused: the destination is archivedUnarchive the destination first.
Move is refused: a template is in useDetach the build configurations from the template first.
