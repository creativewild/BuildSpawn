Upgrade agents

Move a build agent to the files of a new Buildspawn version, and keep its name, its secret, its pool and its work folders.

Before you start

  • You can open the agent machine, and on Windows you have an administrator prompt (on Linux and macOS, sudo).
  • You have the agent download of the new version: Agents › Install agents on the upgraded server (see Install an agent).
  • Pick a quiet time, or mark the agent offline first, so that no build is running (see below).

An agent keeps its name and secret in conf/buildspawn-agent.properties. If you keep that file, the agent does not register again. It stays the same agent, in the same pool, with the same history. Agents that are older than the server still connect, but some features, such as trusted certificates from the server (1.9), the Certificates tab (1.9.2) and the terminal program's certs command, need new agent files.

Steps

  1. Open Agents, find the agent, open the row menu ⋯ and choose Mark offline. Running builds finish first. Wait until the status is Offline.
  2. On the agent machine, close the tray app: right-click its icon, choose Exit, then click Stop agent. (A running tray app would block the new Buildspawn Agent.exe from being written.)
  3. Stop the agent: 
    # Windows, administrator prompt, in the agent folder
stop-agent.bat

# Linux and macOS
./stop-agent.sh
  4. Unzip the new download over the agent folder. When your tool asks about conf\buildspawn-agent.properties, keep your own file. 
    # Windows: unzip over C:\buildspawn-agent
tar -xf buildspawn-agent-windows-x64.zip -C C:\

# Linux
sudo unzip -o buildspawn-agent-linux-x64.zip -d /opt
    Do not delete the work folder. It holds the workspaces, so the first build after the upgrade does not sync everything again.
  5. If you downloaded the zip made for one agent, it holds that agent's secret and may replace the settings file. Use the general download with the file you keep, or copy your old file back.
  6. Install the service again, so that it points at the new files and picks up new Java options: 
    # Windows, administrator prompt
install-service.bat

# Linux and macOS
sudo ./install-service.sh
    Windows says Service "Buildspawn Agent" installed again from … and started. You do not need --url, because the settings file already holds it.
  7. On Windows, open bin\Buildspawn Agent.exe again to get the tray app back. Tick Open this app when I sign in to Windows in its Settings tab if you want it to start by itself.
  8. On the Agents page, open the row menu of the agent and choose Bring back online.

Check it worked

  1. The agent turns Idle on the Agents page, in its old pool, with its old name.
  2. On the agent page its Parameters show the new agent.version.
  3. In the tray app, the Certificates tab is there. In the terminal program, bin/buildspawn-agent-tui --version shows the new version.
  4. Run a small build on it.

Upgrade many agents

  • Do a few at a time, so the pool keeps capacity. Put one agent of each pool through the steps first, run a build on it, then do the rest.
  • Use the Pool Scheduler to lend idle agents to a pool while some of its agents are offline for the upgrade.

Troubleshooting

ProblemWhat to do
The agent asks to register again and appears under Unauthorized.The settings file was replaced and lost its secret. Copy the old conf\buildspawn-agent.properties back (it holds secret=…), or approve the new request. See Connect an agent.
install-service.bat says could not remove the old service definition.Close the Services window (services.msc) and run it again.
The service does not start and logs is empty.Check that bin\buildspawn-agent-service.xml is there. Run install-service.bat again.
The agent runs from a different folder after the unzip.You unzipped to another place. Run install-service from the folder you want. It replaces the old service entry.
The tray app is the old one.Exit it first. A running Buildspawn Agent.exe blocks the new file from being written.
Certificates that you added are gone.They live in work\trust. If you deleted the work folder, add them again (see Trusted certificates).
