Keep the last 30 builds

Stop the disk filling up: keep 30 builds of a build configuration, and the artifacts of fewer.

The Windows Build makes a 2 GB package per build. The studio wants the log and the change list of the last 30 builds, but the package of only the last 5.

Before you start

  • The Configure permission on the build configuration.

Steps

Set the rules

  1. Open the build configuration, click Settings, then General.
  2. Go to Clean-up rules and turn on Discard old builds.
  3. Leave Strategy on Keep by age and number.
  4. Type 30 in Builds to keep. Leave Days to keep builds empty.
  5. Type 5 in Builds to keep artifacts of.
  6. Read the line In words. Click Save.

Keep one build forever

  1. Open a release build.
  2. Click Keep this build forever. The rules never delete it.

Check it worked

  1. Run a build. After it ends, builds older than the 30th disappear from History.
  2. Build 6 and older have no files under Artifacts, but their logs are there.
  3. The pinned build is still there.

Troubleshooting

ProblemWhat to do
Nothing is deletedThe rules run after each build. Run one more.
I need a build that was deletedIt cannot be restored. Pin builds you may need before the rules reach them.
I want the same rule for every build configuration in a projectSet it on the project: Build settings passes steps and parameters. For a server-wide rule ask an administrator.
