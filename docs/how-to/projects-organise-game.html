Organise projects for a game

Set up a project tree for one game, with Main, Drops and Release, so each team finds its builds and shared settings sit in one place.

The studio Skyforge makes one game. It has day-to-day builds from the Main stream, nightly builds that are given to testers (Drops), and release builds that go to the stores. Each group gets its own project inside the project Skyforge.

Before you start

  • The Create permission on the place where the project goes.
  • A rough list of the build configurations you want.

Steps

Make the game project

  1. Open the Projects page and click New Item.
  2. Type Skyforge. The ID becomes Skyforge.
  3. Under Type click Project and click Create.
  4. On its Settings give it a description and an icon, then click Save.

Make the three projects inside

  1. Open Skyforge and click New Item. Type Main, choose Project, click Create.
  2. Repeat for Drops and Release. Their IDs are Skyforge_Main, Skyforge_Drops and Skyforge_Release.

Put shared settings at the right level

  1. On Skyforge open Build settings and add what every build needs, for example the parameter STUDIO_NAME. See Share settings with a whole project.
  2. On Skyforge open Perforce roots and add the root of the depot once. Every build configuration below can use it.
  3. On Release open Credentials and add the store accounts. Only the release builds can use them.
  4. Click Save on each page.

Add the build configurations

  1. Open Main, click New Item, and make Windows Build as a Build configuration.
  2. For the other platforms use Start from Copy of an existing item, or a template. See Create a build configuration from a template.
  3. Give each one its platform icon on General.

Order the tree

  1. Open Skyforge › Settings. In Order of items open the Reorder dialog.
  2. Put Main, Drops and Release in that order. Add a separator if you want a heading. See Tree order and separators.
  3. Click Save.

Check it worked

  1. The project tree shows Skyforge with Main, Drops and Release in your order.
  2. Open a build configuration in Main. Under Settings › Parameters, STUDIO_NAME shows as defined in Skyforge.
  3. The dot after Skyforge shows the worst result inside it.

Troubleshooting

ProblemWhat to do
I cannot see Order of itemsOnly administrators can reorder the tree.
A build in Release does not see the store credentialsCredentials of Release work only for build configurations inside Release. Put the credential higher up only if all builds need it.
I want to move a build configuration between the three projectsSee Move a build configuration.
