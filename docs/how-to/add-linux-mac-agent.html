Add a Linux or macOS agent

Add a Linux server or a Mac as a build agent that runs as a service: systemd on Linux, launchd on macOS.

Before you start

  • You are an administrator in Buildspawn, and you can use sudo on the machine.
  • The machine can reach the server's address, for example http://buildserver:8080/.
  • You know the machine's CPU. Run uname -m: x86_64 means x64 (Intel or AMD); aarch64 or arm64 means ARM64 (Apple silicon on a Mac).
  • Nothing else needs to be installed: the download includes Java.

Steps

  1. Open Agents, click New Node, type a name such as linux-build-02, choose Permanent Agent and click Create.
  2. Set Remote root directory to a full path on the machine, for example /opt/buildspawn-agent/work on Linux or /Users/build/buildspawn-agent/work on a Mac. Add Labels such as linux or macos, and click Save.
  3. Open the agent. Under Download the agent for this node, pick the CPU on the row for the machine's system: Apple silicon or Intel for macOS, x64 or ARM64 for Linux. The file name below changes to match. Click Download.

On Linux

  1. Copy the zip to the machine and unzip it into /opt: 
    sudo unzip buildspawn-agent-linux-x64-linux-build-02.zip -d /opt
  2. To try it first, run it in the foreground. Press Ctrl + C to stop: 
    cd /opt/buildspawn-agent
./run-agent.sh
  3. Install the systemd service: 
    sudo ./install-service.sh
    The zip already holds the server address. The script writes /etc/systemd/system/buildspawn-agent.service, then enables and starts it. The service runs as the user who ran sudo; add --user build to choose another account.

On macOS

  1. Copy the zip to the Mac and unzip it into your home folder: 
    unzip buildspawn-agent-macos-aarch64-mac-build-01.zip -d ~
  2. To try it first, run ./run-agent.sh in ~/buildspawn-agent. Press Ctrl + C to stop.
  3. Install the launchd service. Choose one:
    • ./install-service.sh as yourself: a LaunchAgent that runs while you are logged in. Use it for builds that need the screen, such as iOS simulators.
    • sudo ./install-service.sh: a LaunchDaemon that starts at boot, with nobody logged in. Add --user build to run it as another account.
    The service is named com.buildspawn.agent.

On both systems, ./install-service.sh --print shows the systemd unit or the launchd plist and changes nothing.

The zip holds this agent's secret. The install script makes the settings file readable only by the service's account.

Watch it from the terminal

Every download holds a terminal program. Run it on the machine, or over SSH:

./bin/buildspawn-agent-tui

Press 1 to 8 to move between Overview, Builds, Connection log, Work folders, Service, Settings, Agent log and Certificates. Press p to pause the agent and q to leave. The agent keeps running. See Agent terminal program.

Check it worked

  1. Open Agents. The agent shows Idle, with Linux or macOS under its name and live CPU, memory and disk values.
  2. On Linux, systemctl status buildspawn-agent shows active (running).
  3. On macOS, launchctl list | grep buildspawn lists com.buildspawn.agent.
  4. The log is in logs/agent.log inside the agent folder.

Troubleshooting

ProblemWhat to do
cannot execute binary file or Exec format error.You picked the wrong CPU. Check uname -m and download the other zip.
ERROR: run with sudo on Linux.Run sudo ./install-service.sh. Without sudo, the script can't write the systemd unit.
macOS says the Java in the folder can't be opened.The download was quarantined. Run xattr -dr com.apple.quarantine ~/buildspawn-agent and start again.
The agent connects but builds fail at once.The service account can't write to Remote root directory. Give it the folder, for example sudo chown -R build /opt/buildspawn-agent.

To stop the agent, run ./stop-agent.sh. To remove the service, run ./uninstall-service.sh (with sudo if you installed it with sudo).
