Compare two builds

Find out what differs between a build that passed and a build that failed, or between last week's build and today's: the code, the values, the agent and the times.

Before you start

  • You can see the project: at least the Project viewer role.
  • You know the two builds. In this guide they are Game / Windows Build #2, which passed, and #3, which failed.

Buildspawn has no single "compare" button. You compare the two build pages, which show the same cards in the same places. Open them in two browser windows side by side.

Steps

  1. Open the build configuration and click its History tab. Open build #2 in one window and build #3 in another.
  2. Info line. Under the title, compare the start time, how long it took, who started it, the agent and the changelist or commit. A different agent or a long gap in time often explains a difference.
  3. Summary. Compare Waited in queue, Executed on, Cause and Parameters. For the complete list, click the Parameters tab of both builds. A value that differs, such as CONFIG, is a cause to check first.
  4. Changes. Open the Changes tab of #3. It lists the changelists or commits that are new since #2. When the builds are not next to each other, open the build configuration's Change Log tab: it lists the changes of all builds in between.
  5. Steps. On the Overview tab, compare each step's duration in Build steps. A step that takes much longer in one build is a lead.
  6. Console. Open Console Output in both, switch the Time switch to Elapsed, and compare the blocks. Use Search in log for the same word in both, for example the name of a file.
  7. Tests. If the builds have a Test Result tab, compare the counts. The numbers in brackets show the change against the build before.
  8. Trend. Open the Statistics tab. Hover over the point of each build in the duration, queue time, test count and artifacts size charts to see both values in one place. Filter by Agent to see whether one machine is slower. See The Statistics tab.

A worked example

On the docs server, build #2 of Windows Build took 9 seconds and passed. Build #3 failed after 5.9 seconds.

  • Both ran on win-build-01 with CONFIG = Development, so the machine and the parameters are not the cause.
  • The Overview of #3 says Decided by: Failed: Step "Compile" exited with code 1, and the console shows error C2065: Game/Weather.cpp(88): 'StormIntensity': undeclared identifier.
  • Suppose the Changes tab of #3 lists a changelist by a colleague that touched Game/Weather.cpp. That is the cause. If it says No changes instead, #3 built the same changelist as #2, and you look at the machine, the parameters and the time.

What you see

You can say what is different between the two builds: the code, the values, the machine or the time. If nothing differs, the failure is flaky: re-run the build and see. See Re-run a failed build from the failing step.

Problems and fixes

ProblemWhat to do
The Changes tab says No changes.The build used the same changelist or commit as the build before it. Compare the agent, the parameters and the time instead.
An old build has no times in the console.Builds from before version 1.1 have no per-line times.
I cannot open one of the builds.It may be a personal build of someone else. Ask them to share it.
A build is gone.Clean-up rules deleted it. Pin the builds you want to keep with the pin button in the header.
