Build values

Every value a build step can read: references like %build.number% and the environment variables every step gets.

When to use this page

Use it when you wonder what a step can read. Write a %…% reference in a runner field or a script, or read an environment variable in the process.

How to use a value

  1. In a runner field or a script of Command Line, PowerShell, Python, Node.js, Kotlin Script and C# Script steps, type the reference, for example %build.number%.
  2. In a Shell or Batch step, or in any program, read the environment variable (see the second table).
  3. See Parameter references for the rules.

References

ReferenceWhat it holdsExample
%build.number%, %build.counter%The build number. Not the display name, which a format can fill with parameter values.212
%build.vcs.number%The changelist or commit. With several roots: %build.vcs.number.<id>% for each.48213
%build.branch%The branch or stream without its prefix, of the first root that records one.release/1.4
%build.branch.isDefault%true when the branch is the root's default branch.false
%build.vcs.branch.<id>%The full branch of a root.refs/heads/main
%build.changedFiles.file%The path of a text file that lists the changed files (a name and a status, ADDED, REMOVED or CHANGED).C:\...\changedFiles.txt
%build.checkoutDir%The checkout folder on the agent.D:\agent\ws\Game
%build.is.personal%true in a personal build; not set otherwise.true
%build.triggeredBy.username%The user ID of whoever started the build. For a build another build started, the user who started the first one, when known. Empty for a schedule or a version control trigger.dana.k
%vcsroot.url%, %vcsroot.branch%, %vcsroot.name%, %vcsroot.type%Properties of the root, with one root. Names that look like secrets are left out, and user:password@ is cut from addresses. With several roots: %vcsroot.<id>.url%.//depot/game/main
%agent.…%The agent the step runs on. See Agent parameters.%agent.name%
%tool.<id>%The path of the tool on this agent.C:\Tools\msbuild
%dep.<ID>.build.number%, .build.id, .build.vcs.number, .build.result, .<name>What the dependency build of this chain used or produced. See Build chains.%dep.Game_Cook.build.result%
%NAME%, %env.NAME%, %system.name%Your own parameters.%CONFIG%

Your env. parameters and the values that setParameter set with an env. name are environment variables too. The Perforce variables and the values of version control are described in Version control parameters.

A worked example

Write-Host "Build %build.number% of changelist %build.vcs.number% on $env:NODE_NAME"
Write-Host "Started by $env:BUILDSPAWN_TRIGGERED_BY"

What you see when it runs

Build 212 of changelist 48213 on win-build-01
Started by dana.k

Problems and fixes

ProblemWhat to do
A reference stays as writtenThe value is not known in this build. A %build.vcs.number% needs a version control root that has synced. A %dep.…% needs that dependency in the chain.
%build.triggeredBy.username% is emptyA schedule or a version control trigger started the build, and no user is behind it.
A Shell step does not see a %name% reference replacedShell and Batch steps replace only build parameters and values earlier steps set. Read the rest from the environment.
