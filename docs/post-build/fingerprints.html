Record fingerprints of files to track usage

Records a fingerprint (a checksum) of files, so you can find which build made a file and which builds used it.

When to use it

Use it when several build configurations pass files to each other, for example the engine DLLs that the game build uses. With fingerprints you can answer: "this Engine.dll is on my disk. Which build made it?" and "which game builds used engine build 87?".

How to set it up

  1. Open the build configuration, click Settings, then Post-build Actions. Click Add post-build action and choose Record fingerprints of files to track usage.
  2. In Files to fingerprint type the files, for example Binaries/Win64/*.dll.
  3. Click Save.
  4. Do the same on the build configuration that uses the files, so the use is recorded there too.

A worked example

Engine Build fingerprints Binaries/Win64/*.dll. Windows Build copies the DLLs as an artifact dependency. A fingerprint check shows that Windows Build #142 used Engine Build #87.

What you see when it runs

The build page has a See fingerprints section with the recorded files. Each file shows where else it was used.

Problems and fixes

ProblemWhat to do
No fingerprints are shownThe files did not match. Check the pattern.
A file has no "used in" entryThe other build configuration does not fingerprint it. Archive with Fingerprint all archived artifacts there.
