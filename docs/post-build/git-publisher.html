Git Publisher

Pushes tags, branches or notes to your Git remote when the build ends.

When to use it

Use it to tag a release in Git after a good build, or to push a generated file to a branch. It works with the Git root of the build configuration.

How to set it up

  1. Open the build configuration, click Settings, then Post-build Actions. Click Add post-build action and choose Git Publisher.
  2. Tick Push Only If Build Succeeds unless you want to push after a failed build too.
  3. Under Tags, Branches or Notes click Add and fill in what to push.
  4. Click Save.

A worked example

After Windows Build passes, the studio tags the Git commit of the launcher: Tag to push launcher-${BUILD_NUMBER}, Create new tag on, Target remote name origin.

What you see when it runs

The log shows the git tag and git push commands and their result.

Problems and fixes

ProblemWhat to do
Push rejectedThe tag exists, or the branch moved. Use Update new tag, or Force Push if you really mean it.
Authentication failedThe credential of the Git root must be allowed to push.
