Deploy war/ear to a container

Deploys a web application (a WAR or EAR file) to an application server when the build ends.

When to use it

Use it for web services that you host in a Java application server, such as a launcher back end or an internal tool. Most game builds do not need it.

How to set it up

  1. Open the build configuration, click Settings, then Post-build Actions. Click Add post-build action and choose Deploy war/ear to a container.
  2. In WAR/EAR files type the file or pattern.
  3. Fill in the Context path.
  4. Under Containers click Add Container, choose the server type, and fill in its address and credentials.
  5. Click Save.

Every field

FieldWhat it doesDefaultExample
WAR/EAR filesThe files to deploy, relative to the workspace. Ant patterns such as **/*.war work.Emptytarget/*.war
Context pathThe path the container publishes the application under. A setting inside the file can override it.Empty/launcher
ContainersThe servers to deploy to. Each one has its own address and credentials.NoneTomcat at http://tools.studio.example:8080
Deploy on failureDeploy even if the build failed.OffOff

A worked example

The back end of the launcher builds launcher.war. The post-build action deploys it to the test Tomcat server at /launcher after each good build.

What you see when it runs

The log shows the upload and the answer of the server.

Problems and fixes

ProblemWhat to do
Deploy fails with 401The credentials of the container are wrong.
Nothing is deployedThe file pattern did not match. Check that the build produced the file.
