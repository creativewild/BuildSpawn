Perforce: Publish assets

Submits or shelves the files that the build changed, back to Perforce.

When to use it

Use it for generated files that belong in the depot, for example cooked content lists, or version files. Shelve instead of submit when someone must review first.

How to set it up

  1. Open the build configuration, click Settings, then Post-build Actions. Click Add post-build action and choose Perforce: Publish assets.
  2. Choose the P4 Credentials.
  3. Under Workspace behaviour choose how the workspace is made. The choices are Manual (custom view), Spec File (load workspace spec from file in Perforce), Static (static view, controller only), Streams (view generated by Perforce for each node) and Template (view generated for each node).
  4. Under Publish options choose Submit change or Shelve change, and fill in its fields.
  5. Click Save.

A worked example

After Release Build writes Version/build.txt, a post-build action submits it: Submit change, Only publish on build success on, description Release build ${BUILD_NUMBER} version file.

What you see when it runs

The log shows the changelist number that was submitted or shelved. It appears in the depot history under the build user.

Problems and fixes

ProblemWhat to do
Nothing to publishNo file changed in the workspace, or the paths do not match.
Submit refused by a triggerA Perforce trigger rejected it. Fix the description or use a shelf.
