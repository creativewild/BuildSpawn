Build other build configurations

Starts other build configurations when this build ends.

When to use it

Use it for a simple chain: after the code build, start the tests. For chains that must wait for each other and share files, use dependencies instead. They are easier to follow, and a build is not started twice.

How to set it up

  1. Open the build configuration, click Settings, then Post-build Actions. Click Add post-build action and choose Build other build configurations.
  2. In Build configurations to build type the names, separated by commas.
  3. Choose when to start them: only if this build is stable, even if unstable, or even if it fails.
  4. Click Save.

A worked example

After Windows Build succeeds, Unit Tests and Smoke Tests start. If the build fails, they do not.

What you see when it runs

The new builds show Started by upstream build Windows Build #142. The log of this build lists the builds it started.

Problems and fixes

ProblemWhat to do
A name is not foundCheck the spelling and the path. Names are relative to the project.
Builds start twiceAnother trigger also starts them. Use only one way.
