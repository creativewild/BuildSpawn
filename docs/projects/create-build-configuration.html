Create a build configuration

A build configuration says what to build, where and when. You create one inside a project, then fill in its settings one section at a time.

A build configuration holds the version control roots to fetch, the build steps to run, the triggers that start it, the parameters it asks for, and the rules that decide if a build passed. Each build it runs keeps its own log, changes, artifacts and test results.

Create from scratch

  1. Open the project the build configuration belongs to, for example Game.
  2. Click New Item in the page header.
  3. Under Item name, type a name, for example Switch Build.
  4. Under Type, click the card Build configuration. This is the build configuration with build steps, the visual editor and all the settings homes.
  5. Click Create. The build configuration opens on its Settings tab.

Fill in the settings

A new build configuration does nothing until you give it steps. Work through the settings tabs from left to right:

  1. General: check the name, the Build configuration ID and pick an Icon for the platform it builds.
  2. Version Control: add the Git or Perforce roots to fetch. See Git and Perforce.
  3. Build Steps: click Add build step and pick a runner, for example Command Line or Unreal Engine. See Runners.
  4. Triggers: start builds on a new change or on a schedule. See Triggers.
  5. Parameters: add values the build asks for or passes to its steps.

Each of these is described on Settings homes and has its own page: General, Version Control, Build Steps, Triggers and Parameters. When you are done, click Run in the header to start the first build.

Prefer to draw it? Open Visual editor on the Settings tab and drag steps onto the canvas. The form and the visual editor edit the same settings. See Canvas and palette.

Copy an existing configuration

The fastest way to make a PS5 Build when you already have a Windows Build is to copy it.

  1. Open the project where the copy should go and click New Item.
  2. Type the new name.
  3. Under Start from choose Copy of an existing item. In Copy from, start typing the name of the build configuration to copy and pick it from the list.
  4. Under Settings of the copy, choose what happens to inherited settings:
    • Keep inheriting: the copy uses the settings of the project it is created in. Pick this when the copy should follow its new project.
    • Make inherited settings its own: the copy keeps running the same steps and parameters, whatever the project above holds. Pick this when you copy into another project and want the build to stay the same.
  5. Click Create, then change what differs, such as the platform in the steps.

Overrides are copied either way. The copy gets a new ID, and it starts with no build history.

More on copies and templates: Copying settings. If many build configurations share most of their steps, a template is better than copies: you change the template once and every build configuration follows.
