Build configuration

A build configuration says what to build, where and when. It is the item you use for most builds.

On the New Item page the card carries a small label, Freestyle. That is only its technical name. Everything in the guide calls it a build configuration.

When to use it

Use it for one kind of build: Windows Build, PS5 Build, Unit Tests. It runs steps one after another, gets its sources from one or more version control roots, and keeps its own history, logs, artifacts and test results. It can inherit settings from its projects and templates.

How to set it up

  1. Open the project the build belongs to and click New Item.
  2. Type the name, for example Switch Build. Check the ID.
  3. Under Type choose Build configuration. Click Create.
  4. The new build configuration opens on its Settings tab. Work through the settings tabs from left to right.
  5. Click Run in the header to start the first build.

A worked example

In the project Game the studio makes Switch Build by copying PS5 Build (Start from Copy of an existing item, Keep inheriting). It then changes the platform parameter and the icon to Nintendo Switch.

What you see when it runs

The item appears in the project tree with its icon and a grey dot (never ran). After the first run, the dot shows the result. The page header shows the name, last result, the type chip Build configuration and the ID.

Problems and fixes

ProblemWhat to do
Create stays offRead the line next to it. Usually the name is empty, the name is already used in the project, or the ID is not valid.
The ID is not freeAnother item uses it. Edit the ID, or choose another name.
I cannot see New ItemYou need the Create permission on the project.
