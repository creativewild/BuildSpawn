Perforce polling and triggers

Start a build when someone submits to Perforce, either by asking the server on a timer or by letting a Perforce trigger call Buildspawn.

When to use it

Polling means Buildspawn asks Perforce on a schedule whether there is a new changelist. A Perforce trigger is a script on the Perforce server that calls Buildspawn after each submit. Polling is simple. A trigger starts builds at once and puts less load on the server. You can use both: polling is the safety net.

How to set it up

Poll on a schedule

  1. Open the build configuration, then Settings › Triggers.
  2. Click Add new trigger and add Poll SCM (or, with Perforce Software, P4 triggered build.). Type a schedule such as H/5 * * * *.
  3. Click Save.

See Triggers for the schedule syntax.

Build when the Perforce server calls

  1. Add the trigger Perforce root: build when the Perforce server triggers it to the build configuration. It needs the build configuration to use a Perforce root.
  2. On the Perforce server, an administrator adds a trigger line with p4 triggers that calls Buildspawn after each submit. Use a Buildspawn user that can only build these build configurations, and its API token.
  3. The root shows Commit hook is active or Commit hook is inactive, so you can see whether the server has called.

A Pipeline job reads the note build when the Perforce server triggers it and takes the same trigger.

A worked example

The Windows Build of Skyforge uses root skyforge-main with Minimum polling interval 60. It has the trigger Perforce root: build when the Perforce server triggers it and a Poll SCM trigger H/30 * * * * as backup. A submit at 14:02 starts a build within seconds.

What you see when it runs

The build lists the changelists since the last build. For builds started by a trigger, the cause says run by a Perforce trigger. The build configuration page shows a polling log.

Problems and fixes

You seeWhat to do
No build after a submitThe change may be outside the view or the checkout rules, or removed by a filter. Look at the polling log.
The commit hook stays inactiveThe server has not called yet. Check the p4 triggers line, the user and the API token.
The build triggers itselfIts own submit starts it. Use the filter Exclude changes from user for the build user.
