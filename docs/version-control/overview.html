Version control overview

Choose where a build configuration gets its code: nothing, Git, Perforce or several places at once.

When to use it

Every build configuration has a Version Control setting. It decides what a build checks out, how changes are found, and which builds start when someone submits.

How to set it up

  1. Open the build configuration and go to Settings › Version Control.
  2. Choose one of the options below.
  3. Fill in its fields and click Save.

The choices

ChoiceWhat it isPage
NoneThe build checks out nothing. It has no fields. Use it for builds that fetch their own files in a step.
GitOne Git repository, with branches and extra behaviours.Git
Perforce rootA shared Perforce connection and workspace, defined once.Perforce roots
Perforce SoftwareA Perforce workspace defined in this build configuration.Perforce Software
Several rootsMore than one of the above, each in its own folder.Several roots

More about version control

  • Perforce: the hub for everything Perforce.
  • Version control parameters: the commit, changelist and branch of a build.
  • Versioned settings: keep settings in your repository.

A worked example

Skyforge uses Perforce for the game (Perforce root skyforge-main) and Git for small tools (Git). The Tools Unit Tests build configuration uses Git only. Windows Build uses the Perforce root. The Release build configuration uses Several roots for both.

What you see when it runs

The log starts with the checkout. The build page shows the revision, and the Changes tab lists what is new since the last build.
