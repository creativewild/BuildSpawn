Atom feeds

An Atom feed is a web address that lists the newest builds. Add it to a feed reader or a chat app, and you hear about a failed build without opening Buildspawn.

When to use it

Use a feed when a team channel or a reader should show build results: for example every failed build of the whole server, or the changes that went into one build configuration.

Where the feeds are

The feed links sit at the bottom of the Projects page (the directory), and at the bottom of the History tab of a build configuration. They are links, so you can copy the address with a right click.

LinkAddressWhat it lists
Atom feed for all/rssAllEvery build of the projects in the page, or of the build configuration.
Atom feed for failures/rssFailedOnly failed builds.
Atom feed for just latest builds/rssLatestOnly the newest build of each build configuration. On the Projects page.
Changes feed/job/…/rssChangelogThe changes that went into the builds of one build configuration.

Add the path to the server address, or to the address of a build configuration. For example, the failed builds of the whole server: http://build-server:8080/rssFailed. For one build configuration: http://build-server:8080/job/Game/job/Windows%20Build/rssFailed. Add ?flavor=rss20 to get the same feed as RSS 2.0, for readers that do not know Atom.

Use a feed

  1. Open the Projects page, or the History tab of a build configuration.
  2. Right click Atom feed for failures and copy the link address.
  3. Paste it into your feed reader or chat app.
  4. If the reader asks for a user name and password, use your user name and an API token instead of your password. Create a token under Account in your account menu. See API tokens.

What you see

Each entry is one build. Its title holds the project, the build configuration, the build number and the result, for example Game » Windows Build #7 (stable). The entry links to the build page. A feed only lists what its user may see, so the same address shows different builds to different users. Personal builds of other people are never listed.

Problems and fixes

ProblemWhat to do
The reader says it needs a sign-in.The server needs sign-in. Give the reader your user name and an API token.
The feed is empty.The server has no builds that match, or you may not see them. An empty failures feed is good news.
The links are missing.Feeds are on the Projects page and on the History tab of a build configuration, not on the build page.
