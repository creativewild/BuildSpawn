Parallel tests and composite builds

Split a long test run over several agents so it finishes sooner, and see the results as one build.

Parallel tests

Parallel tests is a build feature. When it is on, one build of the build configuration becomes a parent that starts 2 to 20 batch builds at the same time. Each batch runs its share of the test classes. The parent waits for them and merges the results.

Turn it on

  1. Open the build configuration and go to Settings › Build Features.
  2. Add the feature Parallel tests.
  3. Set the Number of batches, from 2 to 20.
  4. Save.

Each batch needs a free agent, so choose a number your agents can serve.

How the tests are split

  • Maven, Gradle and NUnit steps get their share of the test classes on their own.
  • Buildspawn uses the time each class took in earlier runs to give every batch about the same amount of work. New classes are spread evenly.
  • Any other step can read its share from environment variables:
VariableWhat it holds
BUILDSPAWN_PARALLEL_BATCHThe number of this batch, starting at 1.
BUILDSPAWN_PARALLEL_BATCHESHow many batches there are.
BUILDSPAWN_PARALLEL_INCLUDE_FILEA file with the test classes of this batch, one per line.
BUILDSPAWN_PARALLEL_EXCLUDE_FILEA file with all the other known classes, for tools that only take an exclude list.

For example, a Unity or Unreal test script can pass the include file to its own test filter:

python Build/run_tests.py --classes-from "$BUILDSPAWN_PARALLEL_INCLUDE_FILE"

The results

  • The parent's build page has a Parallel tests block: one row per batch with a link, the agent, the duration and the result, and the merged test counts.
  • A batch build says Batch 2 of 4, part of #12 with a link to the parent.
  • The parent ends with the worst batch result. Each batch keeps its own artifacts and test reports. Mail goes out once, from the parent.
  • Stopping the parent stops its batches.

Pin the revision in the build configuration, or use one Perforce changelist, so every batch builds the same code. Each batch prints its share size in its log, so you can check.

Composite builds

A composite build is a build that only starts and waits for other builds. It uses no agent: it runs on the server, starts at once and finishes when its parts finish. Because it holds no executor while it waits, it cannot take the agent its own parts need.

You meet composite builds in two places:

  • the parent build of Parallel tests;
  • a distributed Unreal Engine BuildGraph build: a hidden setup build exports the graph, the groups run on agents of the matching type, and the parent collects their artifacts.

A composite build shows No agent (composite) in the executor lists, and is not counted as a busy executor. Its build page and log say it runs without an agent. The hidden builds made for it are not listed as build configurations and are cleaned up with the build.

Parallel blocks and Matrix blocks

Parallel tests splits one test run. A Parallel block instead runs steps of one build side by side, on this machine or on other agents. The parts that run on other agents are side builds. A Matrix block runs the same steps for every combination of values, such as platform × config. See Side builds for how they look in the queue and on the build page.
