Personal builds and shelves

A personal build tries your own change, not yet submitted, on the real build steps. It never changes the status of the build configuration, so nobody sees a red build because of your experiment.

When to use it

Use a personal build before you submit a change to Perforce: shelve it, run a personal build of the shelf and submit only when it passes. You can also run a build on your own computer when a build farm slot is far away or you need your own tools.

What makes a build personal

  • A build is personal when you tick Personal build in the Run dialog, when you run shelved changes, or when you pick My machine.
  • A shelve trigger on a build configuration starts a personal build for each new shelf. See Triggers.
  • Only you and administrators see the build. Other people get a page-not-found answer for it and do not find it in build lists, unless you share it.
  • The build configuration's status and its last successful build, for dependencies on that, come from regular builds only. A personal build also does not start other build configurations.

A personal build is marked Personal in the build list and on the build page. Its Summary has a Personal build row, such as Personal build of shelf 260 by dana.k, that links to the shelf.

Run a personal build of a shelf

  1. Shelve your change in Perforce, for example p4 shelve -c 260.
  2. Open the build configuration and click the button with the sliders beside Run.
  3. Open the Shelved changes tab. Tick your shelf, or type its number in Shelved changelist IDs. Separate several numbers with commas.
  4. Click Run personal build.

The build syncs the code, then unshelves each change in the order you gave (p4 unshelve) and merges what is older than the head (p4 resolve -am). If two changes conflict, the build fails and names the files. Then it runs the steps. Step by step instructions with a worked example are in Test a shelved change before you submit.

Run on my machine

With My machine you run the build on your own computer, as a personal agent. Only you can build on it, and only your own builds run there. It is hidden from everyone else.

Add your machine

  1. Open your account menu and choose My machines. You see it only when an administrator has turned on Personal machines under Settings › Security, and you have the Use a personal machine permission (under Agents in the permission table).
  2. Add a machine and give it a name. Buildspawn shows a secret once and an agent download set up for it. Unzip it on your computer and start the agent. It connects by itself, and the page says Waiting for name to connect until then.
  3. Choose how builds use your workspace (see the table).
Workspace choiceWhat it means
Own copy (A)The build uses its own copy of the workspace. The first sync is full.
My workspace (B)The build uses a folder you have already synced, with its Perforce client. The agent unshelves into it and reverts the shelved files after the build, and only when the client has no other open files. A synced folder is never wiped or cleaned up.

Run a build on it

  1. Open the Run dialog and choose My machine · name in Agent, or pick your shelf on the Shelved changes tab and click Run on my machine.
  2. The dialog shows Personal: only you see this build and how many builds the machine runs at a time.
  • When your machine is offline, the build waits for it, up to the time an administrator set under Settings › Security › Personal machines (Offline machine: cancel waiting builds after). Then it is cancelled and says why.
  • An administrator chooses which credentials personal machines may use. A build configuration that uses another credential stops before it starts, and the dialog says so.
  • If an administrator turns personal machines off, your machines stay listed but take no builds.

What you see when it runs

  • The build has a Personal chip. The Parameters tab shows p4.status = shelved and p4.review with your changelist number for a Perforce shelf.
  • The Changes tab lists your shelved changelist.
  • The console says which agent it ran on. On your own machine, the cause reads Personal build on name by you.

Problems and fixes

ProblemWhat to do
My shelf is not in the list.Only shelves with files inside the build configuration's view are listed. Check the view on Settings › Version Control, and refresh the list.
The build fails before the steps and names files.Your shelf conflicts with newer submits. Resolve them, shelve again and run another personal build.
My machine does not take the build.Check that the agent is online, that personal machines are on, and that you still have the permission. The queue shows Only name's own builds run on machine for other people's builds.
The build turned the configuration red.It did not. Look for a regular build that failed at the same time.
