Side builds

A side build is one part of a Parallel block that runs on its own machine. Buildspawn starts it for you, and shows it under the main build.

When to use it

You meet side builds when a build configuration has a Parallel block set to Separate machines, or a Matrix block. For example, one side cooks for PS5 on a console agent, and another cooks for Xbox on another agent. This page explains what you see in the queue, the build list and the build page. How to set the block up is on Parallel blocks and overrides.

How a main build and its sides run

  1. The main build runs its steps up to the Parallel block on its agent.
  2. At the block it starts one side build for each side. Each one needs an agent that fits the side's Run on choice, and fetches the same revision as the main build.
  3. While the sides run, the main build gives up its executor slot on its agent and keeps its workspace. The log says This build gives up its slot on agent while its 2 sides run on their own machines. Its workspace stays reserved for it.
  4. When all sides are done, the main build comes back to the same agent, copies in the files the sides sent back and goes on. If that agent is not free again in time, or went offline, the Fallback of the block lets the build go on on any matching agent.

A main build that started before its block was set to run on separate machines keeps its slot: Starting 2 side builds. This build keeps its slot.

If a side fails or you stop the build

  • With Let the others finish (the default) every side runs to its end. With Stop the others, a side that fails stops the rest: Stopped: another side of ... failed, and the block stops the others. Either way the main build fails after the block.
  • Stopping the main build stops its side builds, and takes the queued ones out of the queue.
  • To run a failed build again without redoing the sides that passed, use Resume: the sides that passed are not run again, and only the failed side restarts, from its failed step.

Matrix blocks

A Matrix block writes the steps once and runs them for every combination of values, for example platform × config. Each combination runs as its own side and can use %platform% and %config%. A block has at most 4 axes and 256 combinations. On the build page you see:

  • a Matrix card with a grid of the results: Success, Failed, Unstable, Running, Stopped, Did not start or Excluded, with counts such as 3 passed, 1 failed;
  • for each combination a Log link and a Re-run button. Run it again. The combinations that passed are not run again. A message says Re-run queued;
  • in the console, a lane for each combination. Click the lane chip to show only that combination;
  • on the build configuration's Overview, a trend of the last builds.

How the block decides what happens when a combination fails (Let the others finish, No new combination starts or Stop the others) and how many run at once are set on the block. See Parallel blocks and overrides.
