The Run dialog

Start a build by hand and choose its options: the agent, the parameters, the changes and the shelves to build.

Run, or Run custom build

The Run button on a build configuration starts a build at once with the default values. A message says Build scheduled, and the build joins the queue. If the build configuration depends on other builds, Run starts the whole chain.

When you want something different for one build, use the Run dialog. Its title is Run custom build.

  1. Open the build configuration, for example Game / Windows Build.
  2. Click the small button with the sliders, right beside Run. Its tooltip says Run custom build.
  3. Choose your options on the tabs.
  4. Click Run Build. Click Cancel, or press Esc, to close without starting anything. Clicking outside the dialog does not close it.

If a parameter's display is set to Prompt, the main button is called Run… and opens this dialog every time. See Parameters.

The Agent list

ChoiceWhat happens
<default: any compatible agent>Buildspawn picks a free agent that fits the build configuration's requirements. A note under the list tells you the label the build configuration runs on, or that it can run on any agent that is not reserved for other build configurations.
Run on all enabled compatible agents (N)Starts one build on every enabled agent that can run it. Use it to try a change on every machine type. It is greyed out when no compatible agent is connected.
My machine · nameOne of your own computers. Only you see this choice. See Personal builds and shelves.
An agent name, under Compatible agentsRuns the build on that agent. Each line shows the agent, whether it can start now (for example Can start now (2 idle)) and its pool.
An agent under Incompatible agentsGreyed out. The line says why it cannot run the build, for example Not in a pool assigned to this project.

The link Compatible Agents under the list opens a page that explains which agents can run this build configuration and why.

A Pipeline picks its agents in its own script, so the Agent list is greyed out and the clean-checkout box is off. Use deleteDir() or cleanWs() in the script instead.

Dependencies

This tab is for build configurations that depend on others (snapshot dependencies). Under Rebuild snapshot dependencies choose one:

ChoiceWhat happens
Default: reuse suitable buildsEach dependency is rebuilt only when it has no suitable build.
Rebuild failed and incomplete dependenciesSuccessful builds are reused. Dependencies whose last build failed or did not finish are built again.
Rebuild all dependenciesEvery dependency in the chain is built again.

Below that, This build configuration depends on N build configurations lists them with their last build. Each one shows the values it will get from this build and where each value came from. The values start from the configuration. You can change one for this run only. See Passing parameters in a build chain.

Parameters

The Parameters tab lists the parameters people can set when the build runs. Each field follows the parameter's value type: a text box, a checkbox, a list or a password.

  • Reset beside a field puts the default value back.
  • A password shows Concealed. Click Change Password to give a different one for this build. Nobody sees the stored value.
  • Hidden parameters are not shown, and read-only ones cannot be changed.
  • A value that breaks a parameter's rule, for example an empty field that must not be empty, is refused before the build starts. The dialog opens on this tab and says why.

If you may not configure the build configuration, you may not change values that end up in script text, and you cannot change Vault parameters. The dialog refuses the change and tells you why.

The values you enter are on the build's Parameters tab afterwards. See Run a build with different parameters.

Changes and Shelved changes

These tabs come from the Perforce plugin.

OptionWhat it does
Changes › LatestSyncs to the newest changelist of the view, as a regular build does.
Changes › ChangelistPick a submitted changelist from the list (search by number, user or description), for example an older one. The build page says which one it was built at.
Changes › LabelSync to a Perforce label. It is greyed out when the Perforce server has no labels.
Shelved changes › Shelved changelist IDsOne or several shelves, separated by commas, for example 16, 17. Tick them in the list, or type the numbers. Empty means a regular build. The build becomes a personal build.
Run personal build / Run on my machineButtons on the Shelved changes tab. See Personal builds and shelves.

If a tab cannot load, for example because the Perforce server does not answer, it says so and offers Try again. The rest of the dialog still works. Git roots have no tab here: to build another commit of a Git root, use Re-run with changes on an earlier build.

What you see when it runs

  • A message says Build scheduled. The build appears in Queue, then on the build configuration's History tab.
  • The build's Summary shows your comment, the agent it ran on and the parameter values that were used. The Cause line says Started by user and your name.
  • With Run on all enabled compatible agents you get one build for each agent.

Problems and fixes

ProblemWhat to do
The dialog refuses an agent: incompatible.Open Compatible Agents and read why. Usually the agent is in another pool or misses a requirement.
My machine says the build will stop before it starts.The build configuration uses a credential that is not allowed on personal machines. Ask an administrator to allow it.
A parameter value is refused.The Parameters tab opens with the reason under the field. Fix the value or press Reset.
The Perforce tabs show Try again.The Perforce server did not answer in time. Click Try again. See Perforce.
