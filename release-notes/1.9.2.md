# Buildspawn 1.9.2 (build 2.589-buildspawn.20)

Installing over 1.9.1, 1.9 or 1.8 keeps your settings and data. Everything in the 1.9.1 notes (`..\1.9.1\NOTES-2.589-buildspawn.19.md`) is also in this release.

How to start it on each system: see `START-buildspawn-1.9.2.html` in this folder.

## Security
- **Script Security 1436.1438.v3dc5ef7d16f2-buildspawn:** fixes a sandbox bypass through a partly written `@Builder` annotation name (SECURITY-4278).
- **Pipeline: Groovy 4403.4405.va_b_cdb_b_d0b_89f-buildspawn:** fixes a sandbox bypass through field values in interfaces (SECURITY-4152).
- The "Warnings have been published" notice for these two goes away.

## Agents
Download the agent again from the server (New agent page) or copy the new files over the agent folder. The agent's settings and registration (`conf\buildspawn-agent.properties`) are not changed.

**Windows tray app (`bin\Buildspawn Agent.exe`):**
- **Certificates tab:** in 1.9 and 1.9.1 the agent download still carried the old tray app, without this tab. The agent itself did receive the server's certificates.
- The old tray app could fail to start on some machines. This one starts.
- When the tray starts the agent, what the agent prints goes to `logs\run-agent.log`. Before, an agent that stopped at start left no log.
- Unexpected errors of the tray app are written to `logs\tray.log`.

**Terminal screen (`buildspawn-agent-tui`, every system):**
- **New view 8, Certificates:** the certificates from the server and the ones added on this machine. Add a certificate file, remove one, see its details, switch the Windows certificate store, restart the agent.
- **New command:** `buildspawn-agent-tui certs list | add <file> | remove <fingerprint or name> | windows-store on|off`, for machines without a screen.

**Windows service:**
- The download includes the service definition (`bin\buildspawn-agent-service.xml`). Without it the service wrapper stopped with only "Unhandled exception" in the event log and no log file.
- `install-service.bat` can be run again on a machine where the service exists, for example after moving or replacing the agent folder.
- `uninstall-service.bat` and `stop-agent.bat` also work when the service definition is missing.
